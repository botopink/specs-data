# syntax-and-comptime-parameters — how an argument arrives

**`comptime x: T` receives a value known at build; `syntax x: T` receives the code as written, not executed at the call; a `-> anytype` / `anyvalue` function builds a type or code; there is no `Expr<T>`, no `.value`, no `Decl`.**

(1) **The two modifiers.** `comptime x: T` is a value known at build, the body holding a `T` (575 (4)); an ordinary function's `comptime` parameter is its specialisation, and an argument not known at build is `comptime-arg-not-known`, read or not (417, 670). `syntax x: T` is the expression written, captured as a tree, opaque in the body — handed only to `compiler.*` or into another tree; a decorator's first `syntax` is the annotated declaration (575 (4), 576 (10)); the modifier is named `syntax` (`expr` is gone), exact for a declaration, an expression or a lambda (616). A `syntax` parameter accepts any expression — a `comptime` value, another `syntax` value, a run-time expression — checked once by the ordinary type check; it guarantees the argument is not executed at the call: the compiler holds the code and evaluates it only where it splices it, so the expression's stage counts there and never at the capturing call (720, 716). `@Expr<T>`, `.value`, `x.fail(…)`, `Decl<T>`, `@Decl`, `Declared<T>` and the old modifier are gone (575 (4), 576 (1), (7)); a `comptime` variadic is one array, `comptime ..sources: Implementation[]` (575 (6), 412 as carried); an optional function-typed `comptime` argument is tested against `null` as any `?T` is — `if (rule == null) { … }` — the function type no exception, 411's `expr-value-of-function` gone with `.value` (735, 575 (4)); the parameters' spelling is 731 (11). `comptime t: type<T>` takes a type and binds `T` (`compiler.typeInfo(city)` with a value is refused); `type<T>` is the type of the type `T`, `anytype` the bare `type` renamed — a type not known until it is built —, `type(` / `type {` the inline type (575 (5), 578 (2)). A function's type parameter is always bound by a parameter, never by the return type alone: `fn get<T>(self: Registry) -> ?T` is refused, `type-parameter-unbound`; `comptime t: type<T>` binds it as Java's class token (668, 667). `v is T` with `T` a type parameter is refused at the test, located, `is-type-parameter`, naming the parameter and the form that works: `v is t` with `comptime t: type<T>`, the concrete type's test in the function specialised for it — a copy per type argument, `t` the type inside it, so `t` handed on to another call is a `comptime` argument known at build (667, 757); or as `t: type<T>` without `comptime`, a run-time value — the type's identity (603), crossing as `Field(Book, "pages")` does (631) — one function, `t` handed on as any value, `x is t` decided at run time by the rules of the literal test (758). A `comptime` parameter may still accept a value or a type where cardume's hooks need it (297, in 575 (5)'s spelling `comptime source: Atom<T> | type<T>`, the body testing `source is type<T>` — 736).

(2) **The tree rule.** A tree — an executor, a meta value, a member, a template's return — holds exactly run-time code (names resolved where written, 384), `syntax` (spliced as the expression held) and `comptime` (parameters and the body's `val`s, spliced as literals); a `compiler.*` call inside one is evaluated at build and spliced as its answer, in every tree, `syntax-captures-build` gone (575 (4), 614, 642); what the build knows always flows into run-time code and only the reverse is impossible: a `comptime` parameter of `Compiler` given a value the tree computes at run time is `compiler-arg-at-run-time`, at the argument, naming the parameter and the value (614, 642). A `syntax` value enters a tree through `compiler.lookup`, spliced as the code it holds, typed where the splice stands; no `Syntax` node (802).

(3) **Expansion at the call.** A function whose body reads a `comptime` parameter and whose every parameter is `comptime` is expanded at its call site: what depends on build data runs at build, each statement that reaches a run-time value is emitted there as run-time code, once per iteration of a build loop, the build-known parts as constants; a loop bound or a condition needing a run-time value is refused at it; a function that also declares a run-time parameter is never expanded (562, 581). A caller's argument that breaks an expanded body is refused at the caller's argument (695). A function whose parameter is `syntax` is expanded at its call: `syntax q: string` takes a template text `` @`…` `` (578); a `syntax` parameter of any other type takes an expression written between the parentheses of an ordinary call — `snap.matches(render(page))` with `pub fn matches(syntax value: unknown) -> anyvalue { val at = compiler.source(value); return code @`snap.matchesAt(${value}, ${at})`; }` — and the body is a build body returning the code that stands at the call (719); the return is any written type — `void` included —, `anyvalue` or `anytype`, `-> T` the code's type checked at the splice (841); a function with a `syntax` parameter is one kind, read by its use — `#[f]` applies it as a decorator, the annotated declaration its first `syntax` parameter, `f(e)` expands it at the call —, each use checked by its own rules against the one declared type, the signature deciding nothing; once B-69 lands it is declared in `src/comptime/`, std or a dependency however it is used (907); `compiler.source(value)` is the call's `Source(file, line, col)`, `file` the file relative to the package root as diagnostics print it (`src/main.bp`), never the module path (756). A `syntax q: string` parameter still takes only a template text — `markup("…")` with parentheses is `syntax-call-outside-syntax` — and a decorator's `syntax decl` stays the annotation's (575 (4), 716, 719). The explicit argument `comptime compiler.src()` is an ordinary parameter and stays valid (718, 719).

(4) **Building types and code.** Any function declared `-> anytype` builds a type: a module-level `val X = f(…)` whose callee answers `anytype` is evaluated at build and `X` is a type, the callee resolved through the import graph, the checker keeping no list of std names; such a function has only `comptime` parameters; a `-> anytype` call anywhere but a module-level `val`'s initializer is `anytype-outside-type-val` (670). `anyvalue` is written only as the return of a template or of a function with a `syntax` parameter expanded at its call, or as `compiler.ast`'s answer, `anyvalue-outside-template` elsewhere (578 (4), 719).

(5) **`comptime` expressions and blocks.** `comptime <expr>` is `comptime { <expr> }` (255 (2), 525); a `comptime` is evaluated at compile time everywhere, calls, loops and records included, on the one comptime runtime, and its value is lifted into the emitted program — a literal as a literal, a record or a collection as its construction, a reference to a top-level function as that reference; a lambda capturing state and a resource stay `comptime-value-not-liftable` (266, 331). A block used as a value answers its last expression written without `;`; `comptime { break v; }` is gone (525). `comptime` is the one crossing from run-time code into the build, `compiler.init` the one crossing from a build body into the program; there is no `runtime` keyword (632). A build value that crosses into run time through a `comptime` has a run-time form the reference states, or is refused at the `comptime` (631).

(6) **`comptime var`.** A module may declare `comptime var name: T = v;`, a variable of the build: written by any build body of its own package — a `comptime` block, a decorator's or a template's body, a function expanded at build — and read at run time as the constant the whole build left in it, folded into the resolved program and its `.bpr` (798, 805); a write at run time is `comptime-var-written-at-run`; `pub` lets an importer read it, never write it (`comptime-var-foreign-write`) — a library's decorator applied in a user's module writes the library's own; a read during the build sees the value at that point, packages in 660's level order and a package's declarations in source order; it holds any value the build can write as code, a host handle or an `Async` in flight refused at the end of the build, `comptime-var-not-writable`; a cached build keeps its final value (793 (4)); a `run()` never recomputes it (806 (4)) (807).

A `syntax` function's `compiler.init` serves both uses — the executor after the annotated declaration at `#[f]`, the executor's body written at the call at `f(e)`; `code` at `#[f]` stays refused, never dropped (986).
