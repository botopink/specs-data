# types-enums-and-patterns — type tests, enums, `case`, namespace types, `?T`

**`is` is only an operator and never tests a type parameter; a bare name is never a pattern; a numeric enum leaf has no sign; a type with no field list is a namespace type.**

(1) **Type tests.** `x is T` is the one spelling of a type test, answers a `bool` and binds nothing — `case` is the only construct that binds (25); there is no `@is` (322). `v is T` with `T` a type parameter is refused at the test, `is-type-parameter`, naming the parameter and the form that works: a type to test against travels as `comptime t: type<T>` — `v is t` the concrete type's test in the function specialised for it (`pub fn get<T>(self: Registry, comptime t: type<T>) -> ?T`, called `r.get(Users)`) — or as `t: type<T>` without `comptime`, a run-time type value tested with `v is t` by the same rules as `v is Users` (records, enums and behaviors by identity, the primitives as each target decides them), both forms in force (667, 758); never a comparison by name (667). The language has `x is fn(<params>) -> T`, a real run-time check (254 as carried). A `bigint` and a `bytes` are not tested by `is` (501, 520). A type parameter bound by the tested value's own type is no free parameter: `v is X<T>` with `X<T>` a member of `v`'s static type (`c: Component<T>`, `c is Composable<T>`) is accepted, tested at run time by `X`'s identity alone, `is-type-parameter` staying for a parameter nothing binds. A behavior's run-time identity is its declaration — module id and name, the atom a type has (`std@context@@Composable`) —, one identity represented by each target (erlang / beam `'__bp_behaviors'/0`, commonJS `prototype["__bp_b_<atom>"]`, wasm the implementors' types at link), read through any import alias, a type implementing `Sub extends Super` carrying `Super`'s too; never a counter, which no target but wasm could assign across packages (831). A union narrows two ways, both in force: by the flow — inside `if (v is A)` `v` is `A`, in its `else` and after a branch that leaves (`return`, `throw`, `break`, `continue`) it is the union without `A`, for a parameter, a `val`, a `var` until assigned, binding no new name —, and by an exhaustive `case` with type patterns, generic ones included (`Composable<T> { k -> … }`), a member with no arm and no `_` refused `non-exhaustive`;: the code every exhaustiveness refusal carries, an enum's and an open domain's too (858); the `if` for one or two members, the `case` where there are many (810).

(2) **Enums and `case`.** A bare variant in expression position is refused at the call, located, naming `E.Two(t)` or `.Two(t)`; a bare variant stays a `case` pattern's (587). A name alone is not a pattern, in a single- or multi-subject arm: `case s, n { Shape.Square(side), m -> … }` is `case-bare-name-arm` at `m`; `_` matches, a variant pattern binds its payload, a constant is `case-constant-pattern` (602). A `?T` is matched by `null` and `_` — `case x { null { … } _ { … } }`, the second arm reading `x!` —, 54's binder arm refused like any bare name (951). A `case` whose arms differ has the union of its arms' types; `[1, "a"]` is `Array<i32 | string>` (150). A `fn` in an enum section body is `section-body-method` (151). A numeric enum leaf has no sign; a negative value is a `Neg { … }` sub-section — `-rotate-12` is `Rotate { 12, Neg { 12 } }`, read `.Rotate.Neg.__12` (314). A value of an enum section prints as the leaf's whole path (601). Numeric leaves stay bare digits (`.__12`) (314). `<pattern> as <name>` is no form of the language (11); a variant's payload is named — an unnamed payload is refused, located, naming the field form (12). A range is Zig's split: `a...b` includes its end and `a..b` excludes it, in a `case` pattern, a loop and a slice alike (53, 105); `start..end` is an AST node, not a value — there is no `Range` value and no `.rev()` (105).

(3) **Types.** A type with no field list is a namespace type: `pub type Type { … }` is legal when every function in its body is associated (no `self`), called through the type; `Type()` is an error naming it a namespace type (329). A type declared in a type is its associated type (330 (7)). `?T` is the one spelling of the optional — `Option<T>`, `Optional<T>` and `optional<T>` are refused, naming it — and `null` the one spelling of absence; the optional is no variant, so `.Some(v)` / `.None` over a `?T` are refused (2, 32, 44, 47, 54); a member access on a `?T` is an error naming `?.` (45); its operators are § result-and-failure (1) (330). An inline `implement B { }` clause on a type is checked as the separate `implement B for X` block is — every required member present (58). A record with no fields is written `type X()`, and the formatter prints the `()` (138). A type alias `type Id = i32` is transparent (307); a generic alias written without its arguments is `type-alias-arity`, a parameter default on an alias `type-alias-generic-default`, an annotation on an alias `type-alias-annotated`, an alias taking a name in scope `type-alias-name-taken` — an alias never shadows —, and `as` on an imported alias is legal (129, 110). A parameter's type may be written inline — `pub fn Link(props: type(href: string, label: string, external: bool = false)) -> Element` —, legal only in a parameter position, a record field or a `val`'s initializer (207, 629 (2), 832); a diagnostic names it by its owner (``the props of `Link` ``) (207). A record field may hold an inline type, `type(…)` or `type { … }`, beside a named one — `pub type RunFailure(kind: type { Failed, Abort }, message: string);` and `kind: RunFailureKind` are both the language —: each inline occurrence is a private nominal type of its module, named by its owner in the reserved space (`Bp__RunFailure__kind`, `Bp__Link__props`), never by a counter (831); readers write `.Failed` from any package and never the name; two identical ones are two types; an inline type inside one is `inline-type-nested` (832). A type implementing a behavior only through an extension block is not a value of that behavior (684). A type's identity is its module and its name (603). `noreturn` is the bottom type: a `noreturn` call fits any position (`val s: string = if (c) "a" else panic("x");`) and ends its path, narrowing after it; a function or a typed lambda declared `-> noreturn` whose body can complete is refused at its name, `noreturn-falls-through`; `panic` is std's one `noreturn` (929). a behavior's statics without `self` are `fn` (628; `Function` itself is gone, 738).

Rows 54 and 951 are read as 980 restates them: a `?T` is matched by `null` and `_` alone, the value read as `x!`, a binder arm `case-bare-name-arm` and a variant pattern over a `?T` refused naming the `null` form.
