# diagnostics — how a refusal and a build error are printed and located

**A refusal prints `error[<code>]: <message>` in one printer, located where the fault is written; a build raise carries its frames; a cell pins the message, the location and the label.**

One printed form for every refusal, parse and checker alike: `error[<code>]: <message>`, the checker's code leaving the message text (557). A refusal cell holds `refused <message>` / `at <file>:<line>:<column>` and, when the compiler prints a label beside the caret, one `label <text>` record, the text as printed; `hint` lines are not claimed (475 (2), 485). `compiler.note`'s text is appended to the mismatch line as `— note: …` (686). A raise at build is located at the call that raised, in its own file, every call of the chain a `called from <file>:<line>:<column>` line, innermost first (532); a type error inside code a decorator added is located at the annotation that added it, naming the member and the decorator's call with its file and line (567); an error in template-built code is located by the word it copies from the template text (691); a comptime arithmetic error reads as Erlang's, located as JavaScript's, at the operator that divides, naming that dividing operation (472, 533, 869); a caller's argument that breaks an expanded generic body is refused at the caller's argument (695). `import-of-failed-module` is one error per importer at its import item, one text for a name and a namespace (545). A refusal names the fix where one exists (`shorthand-import`, `module-import-with-from`, `lambda-untyped`, `fn-return-missing`, `missing ->?`) (337, 206, 583, 622, 525). A diagnostic names an inline parameter type by its owner (207) and prints a backtick identifier in its backtick form (561). An uncaught abort's text is § result-and-failure (535, 556). The `fail` of a decorator reports at the argument or the declaration `at` holds, else at `compiler.src()`, and the body goes on (575 (3)).
