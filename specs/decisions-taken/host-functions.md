# host-functions — `declare fn`, `#[compiler.external(…)]` and `Implementation`

**A bodyless `declare fn` names its host sources with `#[compiler.external(…)]`; a source is host code a target runs, written by its label; a call with no cell for the active target is refused.**

(1) **The form.** A bodyless `declare fn` — top-level or a type's, static included — is refused at the declaration, `declare-without-implementation`, unless an annotation gave it an implementation (575 (6), 604); the only other bodyless declaration is `compiler.bp`'s `declare val compiler` (604, 579). `external` is one std function, `compiler.external(comptime ..sources: Implementation[])`, `Compiler.implement` folded into it (606 (3)); written `#[compiler.external(.Erlang("m:f($0)"), .JavaScript("…"), .Wasm(std: "…"))]` (606 (4), 575 (6)). `Implementation` is the enum `Erlang(template = null, body = null, inline = false, result = false) | JavaScript(template = null, body = null, result = false) | Wasm(template | op | std | wasi | body — one —, host, needs, result)` (610, 619); `Node` was renamed `JavaScript` — a source names the language the template is written in, not a runtime (618); TypeScript is no part of it, no variant, no `types:` field (619). The compiler reads `Implementation` alone; the backends' re-parse of the prelude is gone (575 (6)). A library writes its own source annotation the same way (`#[bif("lists")]`, 575 (6)), over `compiler.external`, `Compiler.implement` being folded into it (606 (3)). `#[@Host]`, `declare` inside a `behavior` (`declare-in-behavior`) and the delegate forms are gone (575 (6)); `@External.Beam` is gone — `.Erlang` binds the erlang and beam targets, `inline: true` declared by it alone, and writing `@External.Beam` is a located error (437). `print` (`io/terminal.bp`) is bound by its cells on every target; no backend intercepts it (575 (6), 606 (2): `println`, `debug` and `todo` are removed). A host template's markers are `$N` and `$args` — on a method `$0` is `self` —; `$self` is refused `template-self-marker`, `$stringify` everywhere (164, 239, 795).

(2) **Labels.** Only the `template` is positional; every other field is written by its label, in any order; a second unlabelled argument is refused, `external-field-unlabelled`, naming the label (621, 487, 305). A template whose text starts with one of the four prefixes is refused on every variant and every target, naming the labelled form — outside std the hint names std's function to call, a `std:` cell being std's own (445) — (516, 847, 883). The compiler's own annotations speak botopink: a labelled argument is `label: value` everywhere, `label = value` a located parse error (305). `body:` is the one name of the botopink-body cell, on `Erlang`, `JavaScript` and `Wasm` alike: a bare identifier naming a private bodied `fn` of the same module whose parameters and return are the declaration's — anything else `external-body-not-a-fn`; a source naming neither `template` nor a cell is `external-source-empty`; an annotation in which every source is a `body:` is `external-all-bodies` — a function whose every target runs the botopink body is a bodied `fn` (610). `op: "f64.floor"` is checked against the opcode table and the signature; `wasi: .Delay` is an enum of the adapters std documents; `std: "hash.contentHash"` names a std-wasm export, checked at the annotation, never resolved as botopink; the prefixed strings (`"fn:x"`, `"std:x"`) are refused naming the labelled form (481, 238, 502). A `.Wasm` cell naming nothing — a `body:` that resolves to nothing, an `op:` missing from the table, an unlisted `wasi:`, a `std:` export that does not exist — is refused by the checker on every target, not on `--target wasm` alone (516). `host: .Wasi | .Browser` only where the hosts truly differ; a binding without `host:` serves every profile (334 (3), 394). `needs: [.Exceptions]`, `[.Http]`, `[.Filesystem]`, `[.Gc]` from a closed enum, a value outside it refused at the annotation (518 (1), 540 (4), 544). `result:` is refused on `op:` / `body:` (491; `fn:` is 610's `body:`). `std:` is std's alone: a `std:` cell outside `libs/std` is a located error naming std's function to call instead (445). `inline: true` on a type method's `.Erlang(…)` cell is refused at the annotation, located (918).

(3) **Strict on every target.** A function whose body reaches a host function with no cell for the target being built is refused at that call, located, whether the function holding it is called or not, in the root package and in a dependency alike (146, 575 (6), 652 — ctr-o closed). A dependency function the program never reaches is not lowered on wasm and stops nothing; a function the program reaches whose body wasm cannot lower is refused at the call, located, naming what it lacks — never at the import (531, 503, 518 (4)). A binding that needs a host feature declares it (`needs:`), the compiler gathers the `needs` of everything the program reaches, writes them in a `botopink.needs` custom section and hands the host only the matching flags; `needs` is no configuration (518 (2), (3)). A function holding a `defer` adds `.exceptions` with no annotation (597).

(4) **Failure of a host.** A binding answers a `Result` from its host only under `result: true`, and then its return is `Result<…, HostError>` or `Async<Result<…, HostError>>` — any other return refused; every way the host fails becomes `Error(HostError(…))`: a raise, a rejecting Promise, an erlang host returning `{error, R}`; `{ok, V}` or a plain value is `Ok(V)`; without the flag a binding promises no failure and one is a crash, contained by `attempt` (490, 431 (2)). `HostError(message, kind, name, detail)`: `kind` always `"host"`, `name: HostErrorName { Error, Throw, Exit }` the same on every target, `message` the host's text (`~tp` without the stack on the BEAM), `detail` the optional stack; only std's `failure.HostError`, by module identity, counts as `HostError` (489, 488). A std module's public function maps `HostError` into the module's own error enum (486). On erlang and beam only a binding declared outside std without `result: true` has its calls wrapped so its raise is marked `host`; std's bindings are audited instead (495) and not wrapped; commonJS wraps every such call (546, 492, 527 (1)).

(5) **At build.** A host function reached in a body that runs at build answers by its wasm form — a `std:` cell or a `.Wasm(body: f)` — the same on every target; one with no wasm form (100 % Erlang or Node, or a real host effect) is refused there, located, naming the cell — `` error: `Rodape` reaches rakun_bpp_render:escape/1, which has no wasm form — it cannot run at build (give it a botopink body, or remove `comptime`) ``; an `.Erlang` cell never runs at build and no translation stands in for a missing wasm form; the build's target does not narrow this (594, 452 (1), 633, 341). Every library gives its pure cells a wasm form, `rakun-bpp`'s renderer first (594 (2)).

(6) **A method with no body in a `type`** is only a host binding; a method declared without a body is a `behavior`'s (311 (1), 575 (6)); a `String` method that moves to botopink on wasm is bound there by a `.Wasm(body: <private fn of primitives.bp>)` cell beside its Erlang and JavaScript cells (618), wasm alone (565).; `slice`'s two helpers among them, botopink bodies the index forms share (879). Host code lives on the type, never on a behavior: a behavior holds signatures and `default fn` bodies and no cell, a type overrides a `default fn` by declaring the member, with or without cells, and `implement-with-body` holds on every bodied declaration, a behavior's `default fn` included (617 (2)–(4)).

Not the rule any more: `#[@External.<Target>]` and the prefixed strings (575 (6), 481), `throws: true` (490), `fn:` as the body's label (610), `@External.Beam` (437), `comptime-host-cell-unavailable` (633), the `Typescript` variant (619), beam-to-wasm as a fallback (452, 594).
