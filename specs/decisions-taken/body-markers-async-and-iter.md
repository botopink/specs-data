# body-markers-async-and-iter — `async`, `iter`, `component`; `Async<T>`, `Iter<T, R>`, `AsyncIter<T, R>`

**A body that compiles specially carries a marker; the return type is written whole, named after its marker; a task behaves as a Promise on every target; every composition of a task is an `async` block.**

(1) **Markers.** The markers, before `fn` and inside a lambda's brace: `iter` (`yield`), `async` (`await`), `async iter` (`yield` and `await`), `component` (`use`, `await`) — `pub async fn`, `iter fn() -> Iter<i32> { … }`, `{ async x -> … }`, `{ iter -> … }`, `{ component -> <div/> }` (553 (1), 584 (1)). A marked lambda's marker is written inside the brace, before the parameters; `async {` is always the block, `iter loop {` the loop, `{ async` / `{ iter` / `{ component` always a lambda; a marked lambda goes wherever a lambda goes, trailing included (584 (1)); its body is a function body — `return v` is the iterator's `R`, a top-level `continue` refused `continue-outside-loop`, `break v` refused (584 (2)). A declaration writes its annotations first, then `pub`, then `default`, then its marker, then `fn` — `#[serverAction] pub async fn count(…)`; any other order is a parse error at the marker (572). A marker is for a body: a bodyless function — a `declare fn`, a behavior's abstract member — writes its return type alone; a marker on one is `marker-on-declaration` (571). The keyword without its marker is refused under the marker's name: `await-without-async`, `yield-without-iter`, `use-without-component`, each hint naming the marker to write; `marker-without-arrow` — every marker written before a brace that opens no block form, `iter {`, `async iter {`, `component {`, with or without `->`, its label naming `{ iter -> … }` and `iter loop { … }` (794) —, `marker-lambda-without-expected-type`, `marker-type-mismatch` stay; `iter-await` refuses an `await` in an `iter` body, the hint naming `async iter` (573, 553 (4)). `async fn f()` with no return type is `marker-type-mismatch`, "write `-> Async<…>`" (584 (3), 622).

(2) **The types.** The return type is written whole, named after its marker: `Iter<T, R = void>` and `AsyncIter<T, R = void>` (`T` each `yield`'s value, `R` the value the iteration ends with — the body's `return v`; `next()` answers `Step.Item(T)` or `Step.Done(R)`), `Async<T>`, `Component<R>`; `@Iterator`, `@Task`, `@Stream`, `@Component` are renamed, and `Task` is no name of the prelude — 606 (1)'s `Task<User>` and 623's `Task<…>` read `Async<…>` (732); a marker whose return type is not its type is `marker-type-mismatch` (553 (2)). Without a marker a body returns the whole type: `async fn load() -> Async<i32> { return 1 }` returns the value, wrapped; an unmarked `fn load() -> Async<i32>` returns an `Async<i32>` itself (`return Async.resolve(1)`), so `fn load() -> Async<i32> { return 1 }` is a type mismatch, the hint naming `async fn` and `Async.resolve`; the same for `Component<R>`; a caller sees no difference (570). A function that hands a value on writes the same signature with no marker; a component's asynchrony stays inferred (553 (5), 375), from its own body only — never because of its children: composing another component only puts its lambda in the tree, and the root is always asynchronous (725; § contexts-and-components (4)). `Iter<T, R>` declares the iterator helpers whole, typed, on every target — `map`, `filter`, `flatMap`, `take`, `drop`, `forEach`, `toArray`, `reduce`, `some`, `every`, `find`; a method outside the set is `unresolved_method` everywhere alike (596). A `component` lambda — `val c: () -> Component<Element> = { component -> … }` — compiles and runs as a `component fn` does, its captures carried, on every target (574).

(3) **Tasks.** `Async<T>` behaves as a Promise on every target: a task settles once, `race` answers the first to settle, `raceOf` runs its thunks concurrently (392 (1), 654). On commonJS and wasm a task starts when it is made and runs to its first `await`, and `await` suspends the awaiting body while other tasks run; on erlang and beam a call answering `Async<T>` answers its settled `T` — `await` the identity, `async { … }` run in place, a combinator that spawns processes (`raceOf`, `runAll`) receiving them before it returns, a pid or a ref never typed `Async` —, so no run-time value there is a task, and no test depends on the difference (335 (2)); on commonJS a task is a Promise, on wasm the runtime's `$task`. `v is Async<unknown>` answers whether `v` is a task, settled or not — `false` for every value on erlang and beam, `instanceof Promise` on commonJS, a `ref.test` over `$task` on wasm — read by std's `run`, the renderer and, on wasm, the `await` that `use c` lowers to (823). `Async<Result<T, E>>` is the task that fails with `E`: its Promise rejects with `E` and resolves with `T`; `Async<T>` does not fail; `val u = try await buscar(1);` propagates, `try await buscar(1) catch User.guest()` handles, `val r = await buscar(1);` is a `Result`; erlang and beam answer the `{error, E}` value, wasm's scheduler settles it with the error; a crash in an `Async<T>` is a defect, contained by `attempt` (432). `map`, `then`, `mapError` and `catch` are withdrawn from tasks: a failing task is read only by `try await … catch` or `case` on `await`'s `Result`; composing without awaiting is an `async { … }` block, itself an `Async` whose value is its tail (`val safe = async { try await load() catch 0 };`) (523, 537 (3)). On wasm an asynchronous function is a resumable state machine driven by a scheduler over `wasi:io/poll` or the JS event loop — no JSPI, no WASI 0.3; a synchronous function pays nothing (392 (2), 504); the wasm backend binds each operand evaluated before an `await` in its statement to a frame local, so a call before an `await` runs once; until it lands the located refusal stays (505). A host adapter may answer `Async<T>` over a generic `T` — `#[compiler.external(.Wasm(wasi: .Delay))] pub declare fn delay<T>(millis: i32, value: T) -> Async<T>;` — its signature checked by shape at the annotation (393); one adapter list for both wasm hosts (394); B-25's gate adapters are `.GateNew`, `.GateOpen`, `.GateAwait` (690). Concurrency fixes results and the order of answers, never interleaving: `spawnAll` answers in input order, `race` the first to complete; no test depends on the order of effects (335 (2)); no cancellation in std's async — a losing racer and an expired timeout run to completion and their results are dropped (704). A module `var` whose type holds an `Async` is refused, located, on every target (547 (iii)). Unchanged: `async` exists only inside `Run` (376 (5)).

(4) **Migration.** Three pieces, each landing per repository: the markers, the types (a codemod), what is new (553 (6)); the codemod adds `async` / `component` to every `-> @Task<T>` / `-> @Component<R>` body that compiled specially without a keyword before the refusal is on (570); the formatter migrates the `marker_*` cells to the brace-first spelling (584 (1)).
