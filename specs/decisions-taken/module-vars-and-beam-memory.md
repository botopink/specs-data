# module-vars-and-beam-memory — a module-level `var`

**A module-level `var` is one value for the whole program on every target; `#[beamMemory(…)]` only picks how the BEAM holds it.**

A module-level `var` stays, its data immutable (`counts = counts.insert(k, v)`), and without any annotation it is one value for the whole program on every target: BEAM a one-row ETS table, commonJS a variable, wasm a permanent root (a global of the module in 544's GC form, a root the collector never frees — 731 (6)); `#[beamMemory(.Ets)]` — the default — and `#[beamMemory(.PersistentTerm)]` (a `var` written rarely and read much) are the two members of a closed enum, any other value refused at the annotation; off the BEAM the annotation is accepted and has no effect (547; amends 167; spelt `#[beamMemory(…)]` by 663). On the BEAM the program's runtime creates every module `var`'s ETS table at boot in a process that lives as long as the program and runs the initializers once; on commonJS and wasm the initializer runs at module load (547 (i)). A reassignment that reads the `var` it writes (`x = f(x)`) is atomic on the BEAM — read, compute, `ets:select_replace` against the value read, retried — so no write is lost; a plain `x = v` is one insert (547 (ii)). A `#[compiler.beamMemory(.PersistentTerm)]` var's `x = f(x)` is atomic too — read, compute, `persistent_term:put` under a per-`var` lock the runtime holds and releases however the writer ends; reads stay lock-free; a plain `x = v` one `put` (903). A module `var` whose type holds an `Async` is refused, located, on every target (547 (iii)) — `module-var-holds-async`, the reach the written type's through type arguments, tuples and fields, never through a function type, a module `val` accepted (905). `keyed: true` and the per-process placement are gone; `Dict.bump` is a plain `Dict` method (547, 340, 534). 376's run-only resource "a module's mutable state" reads "a module `var`" (547 (iv)). A lambda's write to a captured `var` is refused at check time on every target, unless the lambda is a `forEach` body or a local closure called at statement position; a counter shared across calls is a module-level `var` (148). A user decorator on a module `var` is refused at the annotation (710). A module `var` written by a decorator body stays refused (343).
