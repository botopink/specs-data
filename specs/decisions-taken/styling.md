# styling — `css`, `rakun-style`, `rakun-stylesheet`, the theme, scoped styles

**CSS is built in three layers — `css`, `rakun-style`, `rakun-stylesheet` — none of which knows `.bpp`; `rakun-bpp` integrates them; a `styled` value registers in the render's sheet where it is used; `rakun-stylesheet` runs at compile time only; the theme is always declared.**

(1) **The layers.** `css` (`repository/css`, std only): a reader of a stylesheet into a typed `Sheet`, its renderer, and `scope(id, css) -> Result<string, string>` appending `[data-s="<id>"]` to each selector's compounds, leaving `:global(…)` alone (338 (1)). `styled` (now the workspace package `rakun-style`, 724; importing `css` and std): `` styled @`…` `` — its `pub default fn`, a template over the text — answers `Component<Styled>` (`Styled(className, rules)`, implementing nothing of std, 804 (2)); `` styledProperty @`…` `` holds declarations only and answers the record `StyledProperty`, not a component; Tailwind v4's CSS syntax works where it is CSS (`--spacing()`, `--alpha()`, `--theme()`, `@variant`, `@custom-variant`); `@apply` is a `${p}` hole of a `StyledProperty`; `@utility` and `@theme` are refused; a component's class is std's `contentHash` over its rules with the layer's prefix (`s_`; `rakun-stylesheet`'s `e_`); `behavior Styleable { fn toStyled(self: Self) -> Component<Styled>; }` is `rakun-style`'s; the theme mechanism is `rakun-style`'s (338 (2), 381, 661). emilia (now the workspace package `rakun-stylesheet`, with jhonstart-emilia, 724) is a series of components built with `styled`, run at compile time only, importing `rakun-style` and std, no framework (338 (3), 369). None of the three knows `.bpp`, the manifest, `data-s` or `rakun-bpp`; `rakun-bpp` (jhonstart's core before 724) holds the integration — the style function found by `#[bpp.style]`, the scope id, run-time holes as CSS variables (`var(--s-<n>)`, `style="--s-<n>: …"`), the root context `StyledContext`, the sink writing the render's one sheet, and `#[styled(syntax decl, comptime ..items: Styleable[])]` taking the application's `styled` components only (338 (4), 361 (3)). A component activates a scoped style with `use`: `` use styled @`.title { font-size: 2rem; }`; `` or `use cardStyle;`; `html` reads it in the function's hooks and writes `data-s="<id>"` on every element that function's template writes (338 (5)).

(2) **Build and render.** A `styled` literal is computed at build when every hole is known at build — a literal, a `comptime` value, a `val` known at build (another `styled` / `styledProperty` with no run-time hole included), a call of an `Any` function with build arguments —, at render only when a hole is not; the rule is the hole's value, never the literal's text (355, 380). Each hole carries the compiler's mark (known, and the reason when not) from the stages; a literal whose holes are all known is a constant (`styledConstant`); one with render holes is parsed, checked and its known holes computed at build into a template with slots, the render only filling the slots, hashing and registering (377). A `styled` value registers in the render's sheet by its use — `use x`, `#[styled(x)]` —, never where it is made, so creating one reads no context; a module `val` holding a `styled` literal is legal whatever its holes (377, 352). `StyledContext`'s value `StyledSheet` is the render's sheet and layer; a literal computed at render adds its class and rules to the sheet where it is used; a `${p}` splice adds nothing; whoever renders provides `StyledContext` — `rakun-bpp`'s render, `rakun-stylesheet`'s `flush()`; at a prerender it is the build's sheet; `rakun-style` holds no global store and no host cell (352, 378 (3)). `rakun-style`'s reader keeps source order: a declaration written after a nested rule opens a new rule of the class (`.k{background:#ffffff}.k:focus{…}.k{padding:…}`), so token order is class identity; `rakun-stylesheet`'s `flush()` writes the document frame around `Sheet.render()`'s `@layer` blocks (368). A `StyledProperty` used alone — `use p`, `#[styled(p)]` — is refused, naming the fix (381).

(3) **`rakun-stylesheet`.** A tag decorator of its own, `pub fn stylesheet(syntax decl: unknown, comptime ..tokens: Token[])`, `<div #[stylesheet(.Pad.All.4, .Bg.White)]>`: the class (the layer's prefix plus `contentHash` over the rules — `className(cardTokens(), defaultTheme()) == "e_f51c2501"`) and the rules computed at build and recorded as `rakun-style`'s `StyledMeta(layer: Layer, className: string, rules: string)`, one per tag, `setMeta`; `rakun-bpp`'s `html` reads it by type beside `ClassName`, merges `className` into the tag's `class` in annotation order, and its sink writes `rules` in the meta's layer, naming no `rakun-stylesheet`; a family is a compile-time function answering `StyledProperty` (`fn padAll(n: i32) -> StyledProperty { return styledProperty @`padding: --spacing(${n});`; }`); no run-time entry point (`emilia(tokens)`, `className`, `cls`, … leave the run-time API; a class outside a template is `comptime className(.Pad.All.4)`); `<button #[styled(btn)] #[stylesheet(.Pad.All.4)]>` two annotations (369, 367, 382, 383, 301). `rakun-stylesheet` renders what Tailwind 4.3.2 compiles: a family whose output differs moves whole to upstream's form, one helper per shape (`w-1/2` → `calc(1 / 2 * 100%)`, `-rotate-12` → `calc(12deg * -1)`), each new literal asserted against 4.3.2's output quoted in its test (350). Track 06's nine choices — the inline filter chain (`filterChain()`, `backdropFilterChain()`), `BackdropFilter`, `drop-shadow-none` as upstream, the fallback `var(--tw-scroll-snap-strictness, proximity)`, `--inset-shadow-*` without the leading `inset`, `space-*` / `divide-*` with upstream's selector, the `@property` blocks with the `properties` layer declared first and written last, a selector-list modifier as one-`&` variants, `spacingNegHalf(n)` with `spacingHalf` refusing a negative `n` — are 4.3.2's output and hold as the literals' text across s52; the `--tw-*` names are CSS, outside 862 (954). `rakun-stylesheet` adds negative translate (`TranslateX.Neg`, `TranslateY.Neg` by 314's `Neg` convention) and named groups / peers (`GroupNamed(name, inner)`, `PeerNamed`); the named `has` / `not` / ARIA / data / `in` variants and `@theme inline` stay deviations, written with `arbSel` (401, 314). A `rakun-stylesheet` example is `rakun-stylesheet`-only (114). `Important(inner: Token[])` is a modifier of the token set, `AccentAuto` a unit variant beside `Accent(color)` (81).

(4) **The theme.** The theme keeps CSS's flat entry list, typed, and is declared once with `#[theme]`: `#[theme] pub val appTheme = comptime extendTheme(defaultTheme(), [entry(.Breakpoint, "md", Rem(40.0)), clear(.Breakpoint, "lg")]);` — `entry(ns, name, value)`, `clear(ns, name)`, `clearNs(ns)`, `clearAll()`; the name inside a namespace stays a string (CSS's); a token naming a cleared or absent breakpoint is a compile error where the token list is known at build (300). The theme is always declared: an application that expands a `styled` literal has exactly one `#[theme]`, and none is a compile error at the first literal that reads it, naming the fix (`= comptime defaultTheme();` or `= comptime baseTheme();`); `defaultTheme()` is the whole Tailwind theme, palette included; a `rakun-stylesheet` token reading an entry the declared theme lacks is a compile error at the token (358). The `#[theme]` decorator registers its `val` through `compiler.init` and a template emits code reading the registry (`themes.current()`), never a literal; a second `#[theme]` is the registering executor's refusal at init, before `main` (665, 353 → 665; 356's catalogue read is gone the same way, a decorator on a `val` still running with `setMeta` legal, 356). The theme is read while a template expands, where there is no render tree (358, 354 (3)). Dark mode follows Tailwind v4 — `prefers-color-scheme`, the class strategy its documented override —, and the breakpoint functions read the declared theme, so a breakpoint entry works (82, 300).
