# rakun — members, decorators, configuration, stores, the request

**rakun speaks botopink: one decorator per role, in rakun's names; configuration is a typed record per prefix; a store answers `Result<T, StoreError>`; a bean is resolved by type and label.**

(1) **Members.** `rakun` is one repository, a botopink workspace (512) of plug-and-play packages: one directory per package under `modules/`, the package named by its directory, its code's names the package's — no former library's name in a function, a type, a file, a URL or an environment prefix (862, the names as 889, the type `Onze` as `RakunSsr` and `jhonstart-cardume` folded into `rakun-cardume` by 893, the HTML prefix `data-jh-*` as `data-rakun-*` by 898; `styled` stays, the domain's word), each with its own `botopink.json`, `src/`, tests and `AGENTS.md`, the cells under `conformance/<package>/`, one version and tag (`version_set.bp` one row per package, 863), one gate, hook and CI. The packages by layer, each depending on lower layers only (a cycle refused): `rakun` · `rakun-data` (dbcontext + rakun-data) · `rakun-restclient` · `rakun-style` (styled) · `rakun-bpp` (jhonstart, -html, -link, -forms, -test) · `rakun-stylesheet` (emilia, jhonstart-emilia) · `rakun-service` (rakun-web, rakun-actuator) · `rakun-scheduling` · `rakun-session` · `rakun-cache` · `rakun-security` · `rakun-websocket` · `rakun-metrics` · `rakun-messaging` · `rakun-mail` · `rakun-app` · `rakun-ssr` (onze and its eight); the packages a target set keeps apart are three rows of their own — `rakun-ssr-server` (was `onze-server`, erlang), `rakun-bpp-dom-test` (was `jhonstart-dom-test`, commonJS), `rakun-cli` as it is (762). erika is `query`, a repository of its own; `css`, `actions`, `routing`, `validation`, `snap`, `markdown`, `http`, `log`, `json`, `yaml` stay external; the `rakun-starter-*` go and each `*-test` becomes its package's `testing/` module (724, amending 326, 338, 391, 398, 433; the repositories' side is § library-split's). **Plug-and-play:** adding a package to `botopink.json` is all a program does — every module of a declared dependency is in the program (660, 677); a package's module registers itself through its decorator's `compiler.init` executor (581 (2)), the init list in dependency order (580, 660), with its defaults and the program's typed overrides (`#[rakun.config]`); `rakun.boot()` is a plain run-time function over the registry (664); no catalogue is read (576 (7), 665), and a thing registered twice is the executor's refusal at init (665) (724). 187's rule stands inside the packages: a module another always needs is not a plugin; the core absorbs `rakun-actuator-api` and `rakun-logging` and installs `log`'s sink; the span API is the core's; its moves read under 724's package names (187). When one member has to tell or ask another and an edge would be a cycle, the core defines the extension point and the members plug into it — for `rakun-cache` ↔ `rakun-client` a per-tag epoch (`rkTagEpoch` / `rkBumpTag`), `revalidateTag` bumping it, `rakun-client` treating a changed epoch as a miss (185); the epoch only grows, is an `i64`, and `""` is refused in `rkBumpTag` / `rkTagEpoch` (707). The broker and scheduler doubles live in `rakun`'s `testing/` module and reach the registries only through the core's hooks (`rkOnReset("broker-double", …)`, a listener-names term the core owns), importing nothing of `rakun-messaging` or `rakun-scheduling` (938). RSocket's transport is the core's `enum Transport { Tcp, Tls, WebSocket }` and `rkRegisterTransport(t, mount)`, on which `rakun-websocket` registers `.WebSocket` at init; RSocket reads `rakun.rsocket.server.transport` into the enum through its typed config and refuses the boot naming the package to declare when the transport is unregistered — no `rakun-messaging → rakun-websocket` edge (939). Pulsar is not split: it stays in `rakun-messaging/src/pulsar/`; a `pulsar://` listener refuses the boot naming the deferred data plane (274). The outbox relay publishes through `withProducerTransaction` on the in-process broker — `rakun-messaging`'s publisher handed to `rakun-data`'s `relayTick(ds, publisher)` —: sends held, released on commit, dropped on a raise, nothing visible to `read_committed` after an abort; the real-broker run is a `deferred.md` row (160; 937). `jhonstart-styled` merged into the core `jhonstart` (now `rakun-bpp`) (361 (3)). `rakun-cli`'s `release_test.bp` validates the rendered SBOM against the checked-in CycloneDX 1.5 schema with 399's vendored validator (`test/tools/check-schema.js` through `io.process.run`, commonJS), in the test only — never a hand-written schema walker (936). Locale routing is `rakun-app`'s (`i18n.bp`), the BCP 47 subset the `i18n` library's; no `rakun-i18n` member (923). The OTP release renderers are the package `rakun-release` (917).

(2) **Decorators.** One type stereotype, `#[component(lazy: …, scope: …)]`; `#[repository]` is only `rakun-data`'s generator on a `behavior`; one way to provide a bean, `#[provides]` on a free function reading the typed config; the HTTP client is a generator on a behavior, `#[httpClient(EchoConfig)] behavior EchoService { #[get("/users/${id}")] fn user(self: Self, id: string) -> Result<User, HttpError>; }`; one listener, `#[listen(orders)]` on a method, the destination declared once and typed (`pub val orders = Destination<OrderPlaced>("order-events")`); one controller, `#[controller]`, the return type deciding the answer (a `View` is HTML, a record JSON, a `Response` as is); added behaviour around a type's methods is a proxy type the decorator builds (`OrderService.Tx`), around one function a function around the call (`#[retryable]` is `retry(policy, { -> issue() })`); test and security names are rakun's own, no Spring alias (318, 714). A component's lifecycle is said by two behaviors — rakun's `Startable { fn start(self: Self) -> void; }` and std's `Closeable` —, `#[component] type Cache(…) implement Startable, Closeable { … }`; the container runs `start()` after construction when `instance is Startable` and `close()` at shutdown when `instance is Closeable`, the clause checked by the checker (58, 800); `#[postConstruct]` / `#[preDestroy]` are gone; `Lifecycle` stays a module's start mode (925). Each marker registers itself through `compiler.init` with its declaration as code — `pub fn get(syntax decl: unknown, comptime path: string) -> void { val owner = compiler.name(compiler.owner(decl)); compiler.init({ -> rkRegisterRoute(owner, .Get, path, decl); }); }` — and the run-time registry groups by owner; `rkRoutes`, `rkBeans`, `rkHooks`, … go; `bindProperties` / `new` / `gated` are typed members built with `compiler.ast` (625 (1), 605, 626). rakun-restclient's `httpExchange` adds `Api.http()` as a static of the behavior answering an `Api` (627). rakun's `query.bp` names its registration by the declaration's identity, `compiler.owner(decl)` (526). `#[transactional]`'s `Field("clock", Clock)` names rakun-data's `Clock` (669). `rakun.boot()` is a plain function over the registry (664). `#[rakun.module] pub component fn web()` of a dependency registers because the package is declared (660).

(3) **Configuration.** A typed record per prefix: `#[config("rakun.data")] pub type DataConfig(poolSize: i32 = 10, bootstrapMode: BootstrapMode = .Eager)`, bound at boot from the config file and injected by type (`use config(DataConfig)`, or as a bean); a field's key is its exact name and an enum value its exact variant; `#[key("pool-size")]` names another spelling, `#[env("DB_POOL_SIZE")]` an environment variable; a wrong type, an unknown variant, an unknown key or a malformed number stops the boot naming the file, the line and the expected type; `#[value("…")]`, `rkProp*` and string profiles are gone (299). The registry's providers and qualifiers are § registry-and-init (234, 256, 321).

(4) **Stores.** A store has one API, answering `Result<T, StoreError>`: `SqlTemplate.query(…) -> Result<Rows, StoreError>`, `update(…) -> Result<i32, StoreError>`, the ORM repository's methods and every NoSQL store method the same; the `try*` twins go; `StoreError` is an enum in `rakun-data` shared by SQL and NoSQL (`Unavailable`, `Timeout`, `Conflict`, `Constraint`); a rakun-web handler may return `Result<Response, E>` and the framework answers the `Error` (`Unavailable` 503, `Conflict` 409, else 500 with a digest); `panic` stays only for a programming error (304). The document and key-value stores (150 s17) ship `ets:memory`, `mnesia:local` / `mnesia:cluster`, `redis://` and `https://` with one behavior suite against the four; `mongodb://`, `bolt://`, `cassandra://` and `couchbase://` are recognised schemes whose boot refusal names the driver, never a fallback to ETS; the `https://` (Elasticsearch) arm reaches HTTP through the core's `rkRegisterHttpClient`, on which `rakun-restclient` registers its client at init, the boot refused naming the package when none did — no `rakun-data → rakun-restclient` edge (185; 934). Queries and repositories are § query-and-rakun-data (312, 313, 397, 398, 427, 428).

(5) **The request.** A static root's miss falls through, as Next and `express.static` do: a static root is tried first; when no root resolves an existing file the entry answers `chain.next()` and the routes run; only `GET` and `HEAD` are served from a root; a refusal stays final at the entry; `RakunSsr.run` (893) registers `public/` at `/**` before the routes (201). rakun's pipeline provides `RequestContext` (354 (7)); middleware, route handlers and actions are `component` bodies answering `Component<Response>` so they may `use` — `use` without the marker refused, naming it (295, 553 (1), (4), 570). A deferred `after()` that raised or overran is reported through the core logger, the request id as the correlation id (365). rakun's tests that a navigation signal or a `rakun_problem` unwinds through a wrapped binding stay red as library gaps; navigation becomes data the renderer reads (554). rakun-bpp's client router driver takes six functions and is asynchronous; `replaceDepth(nav) = nav.shared - 1`; `markPending` sets and clears `data-rakun-pending` (898); a failed markup clears the mark and answers the error (708). rakun-style: everything is a component, `Styleable.toStyled(self) -> Component<Styled>`; `Sheet.add` stays a plain function storing the component value; `Sheet.render(self) -> Component<string>` is a `component fn` resolving its entries with `use all` (827); `StyledView` / `StyledPropertyView` are removed (661). The SAML 2.0 ACS is retired for the milestone (713). On erlang and beam a spawned child runs behind a port, its stderr merged into stdout (689 — std's rule, rakun-ssr's `start` the consumer). rakun's conformance is one suite read by feature (548). Track 04's implementation choices stand as built under the package names (952): the cache key `namespace + ":" + hash.strongCacheKey(parts)`, a private row with no session running the loader and storing nothing, `rakun.cache.type=none` beating every cache, an action's `revalidate*` expiring at once and `updateTag` legal only there; every messaging arm on the in-process broker (`transport=memory`, a real address refusing the boot naming the driver), a listener container `rakun.messaging.listener.<destination>.*` named by the destination's broker name with Redis's ack mode `none`; a JSON-RPC argument a form-encoded field list read in order into one form; a slot belonging to the nearest layout at or above its shortest entry; the liveness group admitting `livenessState`, `ping`, `diskSpace` only; OTLP pushed as HTTP/JSON; OAuth2's endpoints as `OAuth2Provider` fields and `withClientToken(id, call)` retrying once on 401; the outbox, saga, 2PC and job-store claims by conditional `UPDATE`, resumed at boot. `rakun-cache` importing `rakun-session`'s RESP wire is a downward edge of the layer order, legal. The typed query builder (`Op`, `queryOf`) is the state on feat until `query`'s forms replace it (312, 397, 398). 117 (8)'s "every rakun manifest is `["erlang"]`" reads "every framework package": a package is the unit of its target set (762) and a member repeating the workspace's whole set drops the key (512 (3)). A `.erl` sidecar carrying one of these is the form § library-split retires, rewritten when 150's step reaches it.
