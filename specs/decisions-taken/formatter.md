# formatter — `botopink format` applies the canonical form

**`botopink format` is applied, never checked: the commit hook formats the commit's `.bp` files, the LSP formats on save, and the formatter never fails a gate.**

The formatter is an applier: the `format-check` stage leaves every gate; each repository's commit hook runs `botopink format` over the commit's `.bp` files and commits the result (the version entering the commit, never unstaged changes); no front ends with a reformat step; a language rule stays an error of the parser or the checker, the formatter keeping layout and synonyms alone (524). The rewrites: a trailing lambda whose body is one expression prints on one line when it fits, arrow or not (165); the trailing comma alone decides a delimited list's shape — written with a comma after its last element it prints one element per line and keeps the comma, written without one it prints on one line whatever its width, and a list written open without that comma is joined onto one line; every delimited list (generics, parameters, patterns, imports, types, arrays, record fields, enum bodies, call arguments, tuples); no width rule opens a list (166, 243, 345); both annotation forms are printed as written, neither joined nor split, a comment between blocks staying where it is (286); a template annotation is printed as written (311 (2)); the `;` after a block-shaped statement's closing brace is removed (524); a trailing lambda without `->` gains it, the last `;` of a `case` arm used as a value and the arm's `break <value>` are removed once, making the arm's tail its value, and `comptime { break v; }` becomes a tail (525, 588, 541 (3)); a trailing lambda with no parameter is written `{ -> … }` (541 (5)); elsewhere a block's last expression is printed as written — the formatter neither adds nor removes the tail's `;` (409, 588); `...` as a spread is refused `spread-dot-dot-dot` naming `..`, and the formatter migrates nothing (864); a marker is written in its one order, `#[…] [pub] [default] <marker> fn`, and inside a lambda's brace (572, 584); a backtick name that is already an identifier is written plain (687); a lambda argument's body indents +4 from the call line and its closing `});` aligns with the call, and a lambda with an empty body stays inline (61 (1), (2)); the output is a pure function of the file's content, never of what the file used to look like (65 (2)); a method chain prints on one line or one call per line, never a middle, the continuation indented +4 from the statement (65 (1), (3)); the trailing comma is the one input the canonical form reads (133). 541's lambda-`;` rewrite — removing, once, the `;` of every lambda's last expression statement — stays as `botopink format --migrate 541`, explicit, run by a landing's rebase across the rule, until every repository and open branch is migrated; then a B-27 box removes it (541 (1), 672). The three libraries out of the canonical form (emilia, jhonstart, onze — now `rakun-stylesheet`, `rakun-bpp`, `rakun-ssr`) get one reformat-only commit each, after the formatter carries these rewrites and 529's `..`, so each is reformatted once (524, 541). `format --check`'s structural exemption for an unparsable cell source (155) has no object once the stage is gone (524).
