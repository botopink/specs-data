# strings-bytes-and-text — codepoints, `bytes`, one text on every target

**A string index counts codepoints on every target; `bytes` is an immutable byte sequence with no implicit conversion; every target prints the one text the comptime runtime prints.**

(1) **Codepoints.** `length`, `at`, `slice`, `indexOf` and `lastIndexOf` count codepoints on erlang, beam, wasm and commonJS: `"e\u{301}".length` is 2, `"👍".length` is 1; erlang's templates stop using `string:length/1` / `string:slice/3`; commonJS walks by codepoint only a string holding a surrogate pair; no target counts grapheme clusters (320, 169, 240). `s[i]` and `s[a..b]` slice by code point on wasm too (455). `string.fromCodepoint(cp: i32) -> string` is the primitive the text builders use (262, 641). `hash.contentHash` folds code points: `contentHash("🎉")` is `djb2([127881])` on every target (260). `unicode.normalize` (NFC, NFD, NFKC, NFKD) runs std's own botopink body on the four targets over tables a Zig build step generates from one pinned Unicode version (17.0); `ǅ` in NFKD is `68 122 780` everywhere (333 (A)); the case tables on wasm are data embedded with `compiler.embed` (559). Case maps over all of Unicode; where the JS engine and OTP differ (`ß`, the final sigma), the answer is OTP's (443, 521).

(2) **One text.** A wasm program and commonJS print the runtime's text wherever it differs from the JS engine's: `"${5.0}"` and `5.0.toString()` are `5.0`, `1.0e21` prints `1.0e21`, `trim` uses the runtime's set (space/tab/LF/CR/VT/FF; a NBSP stays), case mapping is the runtime's — including an imported record's `f64` field (441, 521); `NaN`, `Infinity`, `-Infinity` print as those words (444); on commonJS a generic body that writes a `T` as text receives the print shape of each type parameter at the call, one hidden trailing `__bp_ty_<T>` per type parameter used as text, so `show(3.0)` answers `3.0` as elsewhere (673). A template hole writes `print`'s text for every value (530). A value of an enum section prints as the leaf's whole path as written — `Token.Color.White` — on every target; no internal name reaches the output (601). The three generic text methods are `String` methods — now the type `string`'s (641) — `normalizeNewlines()` (`\r\n` → `\n`), `trimTrailingNewlines()`, `firstDifferingLine(other)` (1-based, `0` for equal texts), host templates on both targets (402). The `$stringify` marker is refused in every template, std included; the documented markers are `$self`, `$N`, `$args` (164, 239).

(3) **`bytes`.** An immutable byte sequence on every target (an Erlang binary; a `Uint8Array`; a buffer or GC array on wasm); no implicit conversion to or from `string`, no string literal typed as `bytes`; `bytes.fromUtf8(s)` encodes; `b.toUtf8()` answers `Result`, an `Error` on invalid UTF-8; a binary payload — an upload, a download, an image, a socket read — is `bytes` where it enters (346, 641). Still refused: `bytes` widening to `unknown` (so `print(b)`), a `bytes` template hole, `is` and a type pattern on `bytes`, ordering (`==` stays), `+` between `bytes` and `string`; a `bytes` value may exist at build as a build constant carried in the artifact (520). `encoding`'s byte codecs are botopink bodies over three leaves (585 (k)). A leaf traps outside its domain, the codecs bounding their own reads (880).
