# compiler-module — `compiler`, `compiler.bp` and the compiler's members

**`compiler` is a value std declares, imported like any name; what the compiler does is a member of `compiler`, declared in `compiler.bp`, the first std module.**

(1) **The value.** `compiler` is the default of std's module `compiler.bp`: `pub default declare val compiler: Compiler;` — the one bodyless declaration with no implementation, its value given by the compiler at each point: the annotated declaration in a decorator, the call site elsewhere; `Compiler` is the behavior its members are, whose one implementor is the compiler, a unit test holding the compiler's table to the text (579 (1), 575 (3), 616). A package writes `import {compiler} from "std";`, a std module `import {compiler};`; without the import `compiler` is an ordinary unbound name, and an ordinary name everywhere else (579 (2)). The rules read off the binding (an alias included), not the spelling: `compiler-at-run-time` in a run-time-only body, `compiler-output-outside-decorator`; it is never passed as an argument nor stored (`compiler-escapes`) (579 (3)). The codemod adds the import to every file reading `compiler.` (579 (4)).

(2) **The module.** `compiler.bp` is self-contained and the first std module (`compiler` → `primitives` → the rest, `stdModuleOrder` admitting no cycle): it declares every type `Compiler` names — `SourceLocation`, `Link` (607), `Implementation` with its three enums (606 (4)), `DeclKind`, the handle records `HookNode`, `Method`, `Param`, `DeclAnnotation` (576 (13)), `Span`, `Source`, `ExprContext`, `CustomNode` (576 (5)), `Field<T>` and `Info<T>` (630), the `Node` records of the typed AST (625 (2)) — and there is no `reflection.bp` (608). These types are imported by path, never prelude names: `import {compiler.Span} from "std";` (576 (13), 579 (1)). `Type` — with `partial`, `pick`, `omit`, `merge`, `required` as statics written in botopink — is `types.bp`, which imports `compiler`; `compiler.Field<T>` and `compiler.Info<T>` are `compiler.bp`'s, one name each (630; amends 624). `Annotation` is gone and there is no `Decorator` type (663, 666).

(3) **The members and how each argument arrives** (616, the text the Zig table mirrors): reads — `src() -> SourceLocation`, always with its parentheses, the location of the point where it is written (718), its `file` package-root-relative with its extension, its `column` 1-based as the diagnostics print, and inside a `test "…"` block its `fnName` the test's name (73); `module`, `package`, `isStd` (575 (3), 718); `fail(message, syntax at: ?unknown = null, span: ?Span = null)` (at the argument or the declaration `at` holds, else at `src`; the body goes on) (575 (3), 576 (2)); `note(message)` — appended to the mismatch line as `— note: …`, so a cell's `refused` line pins it (576 (2), 686); `text(syntax e) -> string` (the raw text), `name(syntax e) -> ?string` (`null` for an expression with no name — the implementer decides what a `null` means; on a declaration handle it is never `null`) (575 (3), 643), `source(syntax e) -> Source` (file, line, col of the call), `context(syntax e) -> ExprContext`, `lookup(syntax e, name)`, `bindings(syntax e)` (opaque handles) (576 (2), 686), `custom(ast: CustomNode)` (576 (4)) — a node also carrying the suggestions that fit at its span, which the language server offers at the cursor (803); no `holes`, `isSyntax` or `Syntax` (802); the handle reads — `kind(d) -> DeclKind`, `moduleOf(d)`, `meta(d, comptime m: type<M>) -> ?M` / `metaAll(d, m) -> M[]`, called `compiler.meta(d, Entity)` (727, 840), `attr(d, name) -> ?string`, `component(d)`, `owner(d)`, `hooks`, `fields`, `methods`, `params`, `returnType`, `annotations`, `variants` — each `d.<r>` of old answering what it answered (576 (3), (8)); `compiler.variants(d)` answers `compiler.Variant[]` — name, payload fields, annotations, the enclosing section's name (848); a section wrapper's entry has the one field `value`, typed by the section, its `section` the enclosing one, `null` at the top, and the entries run the top-level variants, then each section's wrapper, its leaves and its sub-sections, in source order (909); `same(a, b) -> bool` — whether two handles are one declaration (an alias and a namespace resolved; a same-named declaration of another module `false`); `==` on handles keeps no meaning (666); `fields<T>(comptime t: type<T>) -> compiler.Field<T>[]`, `typeInfo<T>(comptime t: type<T>) -> compiler.Info<T>`, `optional<T>(f)` / `required<T>(f)` (575 (3), 606 (3)); `embed(comptime path: string) -> Link` (607); `tagDecl(kind: DeclKind, name: string, syntax attrs: unknown) -> unknown` and `annotate(syntax d, at: Span) -> unknown` (636, 576 (2)); the builders `ast(comptime node: Node) -> anyvalue`, `buildType(comptime name, comptime fields, comptime implements = []) -> anytype`, `buildTypeInline(comptime fields, comptime implements = []) -> anytype` (625, 629, 645); the outputs, a decorator's only (`compiler-output-outside-decorator`) — `init(syntax executor: fn())`, `setMeta<M>(syntax value: M)`, `addMeta<M>(syntax value: M)`, `addMember<F>(name, syntax member: F)` and `addMember<F>(comptime target: anytype, name, syntax member: F)` for a type the body built — that form outside a decorator too, the refusal not reaching a built type's members (644) —, `addType(name, syntax source: anytype)`, `external(comptime ..sources: Implementation[])` (575 (3), 576 (9), 615, 616, 644, 606 (3)). Gone: `compiler.find` / `catalogue` (665), `compiler.wrapWith` (714), `compiler.build(text)` (625), `compiler.record` (578 (3)), `compiler.parts` (577 (5)), `compiler.compile` (renamed `init`, 615), `setBuiltin` (606 (1)), `failAt` (576 (2)).

(4) **In a run-time body** each build read is written under `comptime`: `val nodes = comptime compiler.typeInfo(Page).meta(Graph)?.nodes ?? [];`, `val pixel = comptime Asset(compiler.embed("assets/pixel.bin"));` (606 (3), 607 (2)). `compiler` is a `Build` resource (376 (1)) and the one such resource: a type's reflection in a run-time body is `comptime compiler.typeInfo(User)`, a constant spliced as a literal (634 → 575 (3), 632). `typeInfo` answers `compiler.Info<T>` (`name`, `module`, `fields`, `methods`, `meta`, `hooks`) — the one reflection read, `compiler.typeInfo` (606 (3); 248's one builtin and 253's record, as carried); `compiler.Field<T>(name, type: anytype, annotations, defaultValue: ?anyvalue)` is § derived-types-and-fields'.

(5) **Every std decorator is written without `@`**, `#[compiler.external(…)]` with `import {compiler} from "std"` — an annotation `#[compiler.m(…)]` calls the member `m` on the annotated declaration, which is the `compiler` of that point; `#[compiler.stage(…)]` and `#[compiler.beamMemory(…)]` are `compiler`'s members too, one home for every annotation the compiler itself reads (606 (4), 663, 774); `memo` is a function of std's `hooks` module (774). The effect annotations `#[use]`, `#[future]`, `#[generator]`, `#[resultGenerator]` are no std decorators — refused `effect-annotation-removed` (606 (4)).

(6) **`compiler.load(path)`** compiles a file of the package at build — `embed`'s path rules, the file a build input, a package of its own, checked for every target the caller's manifest declares (every target when it declares none), never for the build's `--target`, its target refusals one per host binding (833) — and answers `Result<Module, Refused>` — an opaque `Module` when it compiles, read by `mod.name()` and `mod.path()` (811 (4)), made by its `of` without `pub` that only the lowering's marked call reaches, a program's call of a `__bp_` name refused `reserved-name` (830), `path` the loaded file relative to the package, no target and no dependency list (786, 805 (4)); `Error(Refused(module, diagnostics))` its refusals as `Diagnostic(code, message, file, line, column, label)`, never empty —, read as every `Result` — `val mod = try comptime compiler.load(…) catch { r -> … }` handles the refusals, `try` alone propagates them — and never through `attempt`, which contains only a run-time crash; never a refusal of the caller (780, 782, 783, 786). A `Module` that compiled is run by `mod.run()` in a `compiler.init` body, answering `Result<void, RunFailure>` — std's `RunFailure(kind: type { Failed, Abort }, message: string)`, `.Failed` when the loaded `main` returns `Error(e)` (`message` `e`'s print text, 530), `.Abort` when the package crashes in its body, executors or `main`; `attempt`'s `Failure` unchanged (806 (1)) —: the loaded package is compiled into the program as a package of its own and its `main` called there; a loaded file no `run` reaches stays out of the program; `run` outside an init body and a loaded file with no `main` are refused at build (787). nothing the loaded package runs inside `run()` propagates to its caller, so a failing case never keeps the next from running (806 (2)); the loaded package's `val`s, `var`s, body and inits run at every `run()`, just before its `main`, each run starting clean — an exception to a body running once per program (660) for a package run by `run()` alone —, while what comptime computed is the build's, computed once (798, 806 (3), (4)); `run` is written directly in the init body and may be called twice; the refusals are `run-outside-init`, `run-module-refused` and `load-no-main`, located at the call; the package is named from its path; `Module` is opaque — its constructor std's alone, only `compiler.load` answers one, its fields readable (792). There is no `compiler.snapshot`: the compiler hands the data and writes no snapshot — a conformance module's loaded case is recorded by what its package prints, `cell check`'s records (§ conformance-suite, 789); no `snap` function reads it (796).

`compiler.load(path)` loads a package directory (its own `botopink.json` and `src/main.bp`, its own manifest and targets); a file path is `load-not-a-package`; a conformance case is a package under `cases/<case>/` (982).
