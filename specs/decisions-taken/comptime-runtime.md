# comptime-runtime — one runtime for every target's build, on wasm

**Comptime runs on wasm only, on wasmtime in the native compiler and the page's engine on the web; one answer whatever the build's target.**

(1) **One runtime.** Every target's comptime evaluation — a decorator, a template, a `comptime` block, a host cell reached at build — runs on the wasm runtime; the BEAM comptime runtime is deleted (`persistent_beam.zig`, `runtime/beam/**`, the persistent `erl` spawn, `render_resident`'s erl step), never a persistent Erlang process of any kind; the erlang and beam targets are unchanged — their lowering, snapshots and tests stay; `snapshots/codegen/{beam,wat}/<target>/` became `snapshots/codegen/<target>/` (434 (1)). `botopink build --target erlang|beam` keeps needing `erl` (228's OTP check, the in-memory compile of the emitted `.erl`); only comptime stops needing it — measured by `botopink check --target erlang|beam` and `build --target commonJS|wasm` with no `erl` on `PATH` (436).

(2) **The engine.** The native compiler (`botopink`, `botopink-lsp`) embeds wasmtime through its C API — a prebuilt library per release target, fetched by `build.zig.zon` and pinned by hash, no cargo —; `compiler-web` keeps the page's `WebAssembly`; wasm3 and `modules/wasm3/` are removed; one engine runs a `--target wasm` program and its comptime; what was refused only because wasm3 lacked a feature (exception handling) is refused no more; the compiled-module cache or Pulley is the step's measured choice, never a flag (543); Cranelift with the cache is that choice — Winch compiles neither exceptions nor GC —; a SIGINT in the CLI and a cancel or shutdown in the LSP call `interrupt()`, the build ending `comptime-interrupted` at the body's expression; a second SIGINT, or one with no body running, ends the process at once, exit 130 (901); `attempt` at build catches a checked division by zero as a wasm program does (527 (3), 878). The comptime keeps its arena, freed whole when the build ends (449 (4), 543). A `comptime` body is compiled by the wasm GC backend like any program: no Erlang lowering of comptime code, no term library; the preludes, the reply's codecs and any Erlang-term function the comptime still needs are written in botopink and compiled by the same backend; the reply each cell answers is unchanged (550).

(3) **One answer.** A comptime result is the runtime's answer, whatever the build's target — `string:uppercase` of non-ASCII text, float formatting: one text for the four targets (434 (5)); a wasm program prints the same text (441); commonJS answers it wherever it differs from the JS engine's — an `f64` as text (`5.0`, `1.0e21`), `trim`'s set (a NBSP stays), case mapping (`"ΟΔΟΣ".toLower()` is `"οδοσ"`) (521); case maps over all of Unicode from the generated data, OTP's answer where OTP and the JS engine differ (443); `NaN`, `Infinity` and `-Infinity` print as those words on wasm (444). An unseeded random draw at build is refused with one message — `` an unseeded draw: a build has no entropy, call `random.seed` first (decision 451) ``; the seeded stream (Mulberry32) answers the same value on every build for one seed (451, 456). A comptime record is an untagged map: `is` and a record arm on a comptime value are refused, located, where two records carried into that comptime module share one key set (918).

(4) **Hosts at build:** § host-functions (5) — a `std:` cell or a `.Wasm(body: f)`, else refused, located; math's `op:`-only functions (`sqrt`, `floor`, `abs`, `trunc`, `minF`, `maxF`) carry a `std:` cell beside their opcode, so they fold at build and the program still emits the opcode (764); an `.Erlang` cell never runs at build; nothing in botopink calls beam-to-wasm (452, 594, 633). `modules/beam-to-wasm/` — a standalone translator, `.beam` in, wasm out, on std-wasm, nothing of botopink (438) — receives no work and is deleted with 164's B-84 (544).

(5) **Snapshots.** A codegen snapshot writes in full only the module under test and the code generated for it; a function of any other package — std, a library, whatever its source — is one line naming it with its hash, the body omitted; the binary that runs stays complete (558, extends 446). Where a step rewrites the comptime's lowering, every `COMPTIME REPLY` and every cell's text stay byte for byte, the oracle; the `COMPTIME WAT` is re-recorded once per piece and its diff read (558 (2)).

(6) **Order:** the B-00 group opened before any other step of any front; the wat runtime's limits are the only runtime's limits (434 (6)); the render-resident / at-build path of 378 (4) is 594's.
