# typed-ast-code-and-mocks — `compiler.ast`, `Node`, `code` and `mock`

**Code never enters the compiler as a string: it is written (a `syntax` parameter, a template text) or built as the typed AST; `compiler.build(text)` is gone.**

(1) `compiler.bp` declares the language's nodes as records — `Node`, a closed union alias of its kinds — `pub type Node = Name | Lit | Member | Call | Arg | List | Tuple | Binary | Unary | If | Lambda | Fn | …`, one record per kind of the parser's `ast.Expr`, `Call(callee, args)` (`fn` is reserved), `Fn(params, ret, body)` a typed function beside the untyped `Lambda`, and the type nodes, one per kind of the parser's type grammar; no `Record` / `Field` / `Case`, a construction being a `Call` with `Arg`s (751, 753) — and `compiler.ast(comptime node: Node) -> anyvalue` builds code from a tree, typed where the call stands, its argument checked in the reply (625 (2), 751); a type error inside the tree is reported at the `ast` call, located at the caller's call, the message naming the library's `file:line:col` of the `ast` call and the node, a splice of the caller's code keeping the caller's own location (752); a template that answered the caller's text as code takes the caller's code as a `syntax` expression and splices it, reached by `compiler.lookup` (802), `pub fn located(syntax q: unknown) -> anyvalue { return code @`${q}`; }`, an error in it located at the caller's text, and a build value that became code through a string is a hole of `code` (801); `compiler.build(source: string)` is gone — a string the compiler parses back is code nobody wrote (625 (2)). `compiler.ast` is admitted in a decorator body too (640 (3)). `syntax` is a modifier, never a type: no `Syntax` node exists; a `syntax` value — a template method's receiver, any `syntax` parameter — reaches a tree through `compiler.lookup` (802, reversing 638).

(2) **`code`.** `code.bp` is a std module imported where used (`import {code} from "std"`), whose template `code` turns code written with `${…}` holes into the AST — `` code @`Element(tag: ${tag}, kids: [${kids}])` `` —, each hole's name resolved with `compiler.lookup` — a `Node` value spliced as that node, a `Node[]` in a list position as its items, any other build value a literal, a `syntax` value as written —; a node that does not fit its position refused at the `code` call; no `Hole(index)` node, no new keyword; built first, inside B-149 (625 (4), 637, 802). `code` is one way, not required: each template's syntax may use the compiler's build methods directly — `compiler.text`, `compiler.lookup`, `compiler.ast` — with its own parser (802).

(3) **Mocks.** std's `testing/mocks` is the one mocking module, lib-agnostic, no copy per library (71); a mock is a std function over the behavior, `val g = mock(Greeter);`, not a decorator on it: `testing/mocks.bp`'s `pub fn mock<T>(comptime t: type<T>) -> T` runs at build, builds an anonymous inline type implementing the behavior — `compiler.buildTypeInline(fields: [Field("__id", string)], implements: [t])` —, adds one method per member of `t` with `compiler.addMember(M, compiler.name(m)!, code @`fn(self: Self, ${params(m)}) -> ${ret(m)} { return invoke(self.__id, ${name(m)}, [${keys(m)}], ${def(m)}); }`)` and answers `M(__id: newMock())` typed `T`; `#[mockable]`, the associated `Mock` type and the `mock()` member are gone; whether a type can be mocked is the test's business (644, 645). `testing/mocks`' registry lives in the wasm module's own memory (335 (3)).

(4) **Order:** B-149 — P1 the `Node` records and `compiler.ast`, P1b `code.bp`, P2 the template cells over `code`, P3 `compiler.build` removed, P4 `buildType` over fields; 165 s11 then moves rakun-bpp's and rakun-style's generators over `compiler.ast` (625, 637, 640).
