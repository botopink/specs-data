# actions-http-log-routing-i18n — the small shared libraries

**`http` is the one cookie reader and q-value parser; `log` owns levels, records, the digest and the sinks; `routing` the file-kind conventions; `actions` the action id and the `Result`-answering action.**

(1) **`http`.** `import {cookie, accept} from "http";` — one cookie reader, one q-value parser, one home for the header codecs, target-agnostic, consumed by rakun and `rakun-ssr`; rakun's four `Cookie:` readers and the three q-value parsers are deleted (196). A duplicated cookie name: first wins, everywhere (RFC 6265 § 5.4) (181). One strict q-value grammar: at most three decimals, digits only; anything malformed reads as 0 (182). `Cookie<T>` lives in `http`: a cookie is declared once, typed — `pub val sessionCookie = Cookie<SessionId>("session", httpOnly: true, secure: true, maxAge: days(30));` —, `T` one it can encode (string, number, `bool`, enum, one-field record) (294). `io/http`'s `fetch` has one typed surface: `pub type Request(method: Method, url: string, headers: Header[] = [], body: ?bytes = null)`, `HttpError { NotAllowedOnHost, Network(message: string), Timeout }`, `pub fn fetch(req: Request) -> Async<Result<Response, HttpError>>` (`Async<T>` is the one name, 553 (2); 606 (1)'s `Task<User>` and 623's `Task<…>` read `Async<…>`, 732); `val r = await fetch(Request(method: .Get, url: u));` — a short GET is the record with its defaults, never a second signature; `fetch(url)` and its `string` error are gone, a `string` argument refused by the checker's own `expected Request, got string` (623, 335 (1)). A query component or a cookie chunk whose escape is malformed or decodes to a control character is refused — `querystring.parse` / `parseForm` answer `Error`, `cookie.parse` / `get` answer the chunk as absent — never kept as written; rakun's own readers go with 196 (915).

(2) **`log`.** `import {digest.errorDigest} from "log"; import {logging.Logger} from "log";` (each name from the module that declares it, 763; 195's leaf form was an example of its time) — levels, `LogRecord`, four renderers, `errorDigest` and a `Logger` whose sink is injected, target-agnostic; `RenderHooks.onError` is not added: `rakun-bpp`'s boundary calls `log`'s `logError(module, errorClass, message, topFrames, fields)`, `module` the boundary's route segment, and answers the digest; with no sink set the default sink (erlang `logger` / node `console`) receives it (195, 220). One error-digest scheme with one implementation: the first 16 hex of `strongHash` over `module|errorClass|message|topFrames`, frames normalised (the first three, line numbers stripped), `errorDigest(module, errorClass, message, topFrames)` in `log`, pinned by one known-answer fixture on every target; no library computes a digest any other way (194). `log` owns the sinks — console, a file with rotation, per-name levels — and `log.captureRuntimeReports()` (BEAM: the OTP `logger`'s reports; node: `uncaughtException` / `unhandledRejection`; wasm: a no-op); it imports on every build; rakun and `rakun-ssr` only choose, configure and install a sink at boot; of rakun's logging cells only the correlation id stays rakun's (349). `log.fileSink` is one API on every target and answers a named `Error` on wasm, on both hosts, at the one call that cannot be served — `Error("log.fileSink: a wasm program has no file system - use consoleSink")` —, `consoleSink` working there (405). A deferred `after()` failure is reported through the core logger, never deleted (365). `consoleSink` writes through `terminal.print`; `fileSink` rotates as OTP's `logger_std_h` does and answers `Error` of `log`'s enum on a failed host call, never a raise; per-name levels and `captureRuntimeReports` as built (921).

(3) **`routing`.** `conventions.fileKinds()` is in the order the kinds wrap a page, outermost first: `layout`, `template`, `error`, `loading`, `not-found`, `page`, then `default` and `route` (171); a file kind's wire letter is `conventions.kindLetter(kind)`, the inverse of `table.kindLabel`; rakun-app keeps no private map (172); `conventions.classify(appDir, path) -> ?ConventionFile` takes one path; a list is `conventionConflicts(entries)`'s (173). `rakun-ssr` consumes `routing.conventions` and derives no chain of its own (323). `routing` holds every piece of routing code server and browser share — `segment`, `table` (the route table's wire), `match` (`matchPath`, `layoutChain`), `route_kinds` (the `k` blob), `slot_states` (the `z` blob), `url_rules`, `navigation` (the `nav:` reasons — `nav:not-found` 404, `nav:redirect:<loc>` 307, `nav:permanent-redirect:<loc>` 308, `nav:see-other:<loc>` 303 — and the `n` codec) and `pattern` (the `:param` grammar: `parsePattern`, `matchPattern`, `patternProblem`) —, neutral: no HTTP, no state, no host cell (115 (1), 116 (1), (9)).

(4) **`i18n`.** `i18n` owns one BCP 47 subset: a language of 2–3 letters, an optional 4-letter script, an optional region of 2 letters or 3 digits, case normalised; a tag outside it is refused, never passed through (180).

(5) **`actions`.** An action answers `Result`; there is no `ActionOutcome`: `#[action] pub fn signup(input: Signup, ctx: ActionContext) -> Async<Result<Subscribed, ActionError>>`; `ActionError` is a sum type whose cases are the outcomes, each an HTTP status on the wire — `Input(fields: Dict<string, string[]>)` (written by the wrapper; the function never runs), `BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `TooManyRequests`, `Internal`, each `(message: string)`; `ActionErrorCode` and `orError()` go; the envelope's `{data}` / `{error}` JSON is protocol only and never reaches bp code (303). One function derives an action id: `actions.id.deriveActionId(secret, module, name, buildId)`, `isActionId(id)` for the grammar; rakun-app's wrapper is deleted, the secret read from the `#[config("rakun.actions")]` record (324). `actions` holds every text both sides of an action read or write — `state` (`ActionState`, the `state` grammar), `envelope` (the v1 envelope, `v` first, `redirect` derived from `n`), `rpc` (`{"v":1,"id":…,"args":[…]}`, an unknown `v` an `Error`) and `refresh` — and names no field and no header: `actionField` / `actionHeader` come from the orchestrator, defaults `__bp_action` / `X-Bp-Action`, and rakun with either key unset refuses to start the dispatcher, naming the key (116 (2), 114 (7)).
