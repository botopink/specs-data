# contexts-and-components — `Component<R>`, `Composition` / `Composable`, `Scope`, `use`, contexts and the hooks list

(0) **The three names (809, 815).** `pub type Composition<T> = fn(scope: Scope, key: Place) -> T | Async<T>;` (what runs: a function opening its own cell with `scope.childAt(key)`, the key replacing the place its value carries; a lambda of one or no parameter is a component without hooks (888); a call by hand passes its place and is safe, 815, 819, 820) · `pub behavior Composable<T> { fn compose(self: Self) -> Composition<T>; }` (what a type implements) · `pub type Component<T> = Composition<T> | Composable<T>;` (what every program writes; none declares or implements it — `implement Component<…>` is refused naming `Composable` (`implement-component-not-composable`, 828)), in `primitives.bp`'s compiler section (826; 809 (1)'s `context` module amended), `Scope` and `Place` `context`'s. The type form is `type Card(…) implement Composable<Element> { component fn compose(self: Self) -> Composition<Element> { … } }`, the `component` marker on `compose` required (it makes the body the `Composition` over the scope, and `use` exists only under it), 800 comparing the signature without it; `Card(…)` answers a `Card`; `component fn` is the short form, a call answering a `Composition` and running nothing, its return written `Component<T>` or `Composition<T>`. A component body answers `T`, an `Async<T>` or a `Component<T>`, the last resolved before it returns with a child cell (816 (6)), a `use c` with a child cell found again or made at its place (817), a `use provide` counting in the order written (812), so `Component<Component<T>>` never arises; a `T` that is a `Composition`, a `Composable`, a `Component` or an `Async` is refused where written. std's `resolve<T>(c: Component<T>, scope: Scope, key: Place) -> T | Async<T>` (`if (c is Composable<T>) return c.compose()(scope, key); return c(scope, key);`, 815, 819) is the way a component runs — `use c` passing `Place.none()`, the renderer's child list `Place.index(i)` (820, 891) —; a root runs it with std's `pub async fn run<T>(c: Component<T>, scope: ?Scope = null) -> Async<T>`, `resolve` with `Place.none()` awaited only when it answers an `Async`, making and closing its own root when handed none: `val page = await run(App());` (822, 825); awaiting nothing inside: an `await` only where the hooks list marks the node (375, 725), so being a component asks no `await` of its callers (661); `x.compose()` is refused outside std's `resolve` (804 (1), 815); a function answering a member of a union fits where one answering the union is expected, so `{ _ -> e }` is a `Composition<T>` (815). rakun-bpp's builders are `component fn`s and `NodeChild = Component<Element>`; a ready value enters as a plain lambda, `{ _ -> v }` (815) — `{ component -> … }` is 574's factory, refused where a `Component<T>` is expected (817 (3)) —; a list item is keyed at its call, `#[key(p.id)] Item(p)` (818 (3)), and rakun-bpp keeps the resolved tree in a record of its own beside `Element` (813). `Scope` (was `RenderScope`): opaque (`Scope.root()`, `scope.childAt(key)`), a mutable cell over a persistent map of contexts keyed by a context's key type (its value's type, or 416 (2)'s behavior); a child's cell found again by its place alone — the call's number within its declaration and the item's number in that render, or the `#[key(…)]` value in the item's stead, no callee name, no type (818, 819) —, written into the value by the call that makes it, a runner's `key` replacing only the item's half (820) — the number counted within the nearest `component` body, the lambdas written in it counted with it and the item's counter kept in its cell; a call written there answering a component stamping over what a plain function stamped; a function answering a component named there as a value (`itens.map(Card)`) numbered where written, each value it makes counted on it; a plain function's calls numbered within it, its counter reset at each entry (821) —, reused while it matches, fresh otherwise, its contexts taken anew from the parent at each render and only its hooks' slots kept (817); a node's `use provide` replaces its own cell's map, reaching its subtree alone, and its `use context` reads the map received at entry (354 (2)); a `Composition` answers its value alone. On erlang and beam the root's tree is one process-dictionary entry keyed by the root's ref — ended with its process or by `root.close()` (a root is `Closeable`, 539), which marks it closed on every target, a use after it failing `scope-closed` (825), `close()` on a cell that is no root failing `scope-not-root` (896) —; a scope reaches another process only as `scope.detach()`, a fresh root over its contexts, what a streaming fill carries (824): a seed, whose tree starts in each process at its first read and ends with that process or with `close()` called there, the cells of an ended tree failing `scope-closed` while the seed read again starts anew, no entry left behind (897). Every `use` that answers a value — a hook or a component — takes a child cell at its place (the call's number, 819), the node's own cell holding its contexts alone (818 (1)), and a cell is kept from render to render while the same call (and key) stands at the same place (818 (2)), as React keeps a fiber — a different component there starts fresh; a type form keeps state as a `component fn` does; the render library keeps a mounted tree's root; a call by hand, `c(scope, place)`, takes the cell its place names, as any other run does (816, 819).

**A component is a `Composition` over an opaque `Scope` (809); calling it only makes the lambda and the render library runs it; a context is named by its value's type, read through an imported context value, provided by `use provide(ctx)`; every `use` is top-level and runs on every call.**

(1) **The wrapper and the lowering.** `Component<R>` is std's and the only wrapper — no `@Hook`, no `Renderable` —, the language's one concept of a component whatever its `R`: it does not tell a component from a hook nor knows what a tree's node is; a `Component<R>` is read with `use` in a component body and run as a child where a library's type admits it (354 (1), 553 (2), 804 (2), (3)). A call of a component only makes its lambda, in a component body too (791 (1)); what a tree holds is the render library's: rakun-bpp's `Element` is its HTML AST, `NodeChild = Component<Element>` one child and `NodeChildren = NodeChild[]` the list, no coercion (804 (4), 809 (7)); a deferred child — a boundary's, a `Suspense`'s — is a component value, never a `fn() -> Element` thunk (930); the renderer resolves every child, a type-bound one through its `compose`, the root run by the render library (791 (2), 809 (6)). At run time a component is a `Composition`, a function over an opaque `Scope` (809): `component fn Card(item: Item) -> View` lowers to a function answering `(scope, key) => …`, the call stamping its place on it (819, 820); the call `Card(i)` runs nothing, so `itens.map(Card)` answers lambdas and generic code needs nothing of a component (388 (1), 653). An alias of `Component<T>` (`View`) is erased everywhere, a return included — the marker activates, never the return (553 (2), 852); an alias implements nothing, its `R` does (826 (4), 850); no decorator asks what `R` implements (804 (2), 851). std's `context` module declares `Scope` — opaque, made only by `Scope.root()` and `scope.childAt(key)` (817, 819) — and `resolve(c, scope, key)`, answering the component's value (388 (2), 809 (6), (8)). The render library — `rakun-bpp`'s renderer — holds scopes explicitly: the root with `Scope.root()`, each child run with `resolve(child, scope, Place.index(i))`, the child opening the cell its place names, the index filling only an item half no component body counted (817, 820, 891), a kept value with the cell it kept (388 (3), 414, 809 (8)). Inside a component body `use c` runs the component `c` with the child cell at its place (812, 817) and answers its `R` — `val tree = use view(props);`, a component resolving a component, and nowhere else (791 (3)); a run-time list of components is resolved by one `use all(cs)`, std's hook answering `Component<T[]>`, each entry run at `Place.index(i)`, which fills a missing or a plain function's item half and never a body's count or a key (827, 884, 891); `await` is for `Async` alone — a call answering `Async<T>`, in an `async` body or a component body (553 (1)) —, `await c` over a component refused `await-component`, naming `use c` or `c` as a child (791 (4)); outside every body — `main`, a test, a render library's root — a value runs with `await run(c)` (822, 825); at build the comptime runtime runs it with `Scope.root()` (388 (4), 378 (4)). The scope travels explicitly: no "current context" stack, no `AsyncLocalStorage`, no process dictionary, nothing captured (388 (5)); on erlang and beam the root's tree is one process-dictionary entry, on commonJS a plain object, on wasm a heap cell (824, 883). Components compose by data on every target: only a body that awaits is a state machine, the renderer awaits only marked lambdas; a component that composes others stays direct; the tree it answers holds component values (`<main>{view()}</main>` stores `view()`'s lambda); `Suspense(fallback, child)` and `ErrorBoundary(child, view)` are tree nodes holding component values, run by the renderer while descending — inside a `Suspense` the child is rendered with the scope the node was met with; if the subtree finishes without a marked lambda the HTML is emitted directly; at the first marked lambda the fallback is emitted, `(child, scope)` kept, and the fill runs `renderComponent(child, scope)`; `ErrorBoundary` runs its child under `attempt` and renders `view(infoFor(failure))` with the same scope; a page with no marked node renders without streaming (504, 414). Every form is a component — a method, a lambda, a `default fn` answering `Component<R>`, and a type implementing `Composable<R>` whose `component fn compose(self)` is its body (593, 804, 809 (2); § records-and-props (3)). A `component` lambda runs as a `component fn` (574). Being a component asks no `await` of its callers (661). Hooks live in a `component fn` body — the marker is what admits `use` (553, 722).

(2) **Contexts.** A context always declares its default, named by its value's type: `pub val themeContext = comptime createContext(Theme(primary: "#e11d48", radius: 4));` in any module (378 (1), 379 (1), 722). A context is read through a context value the reader imports — `import {themeContext} from "theme"; … val t = use context(themeContext);` — never a bare type name; `t` is a `Theme`; the read answers the nearest context of that type provided above, else the default the handle carries; the handle is imported as any name, so no catalogue is searched (722, 723). The argument is that name alone — a parameter, a local or an expression at it is `context-not-declared`, located, because the hooks list and 379 (6) read the declaration it names (839). `use provide(ctx)` takes a context value alone — there is no `(ctx, value)` form; a component that provides another value makes a context of the same type in its body, `val c = comptime createContext(Theme(…));` (a build value) or `val c = use memo({ -> createContext(Theme(…)) });` (run time: std's `memo<T>(make: fn() -> T) -> Component<T>`, computed on the component's first render and kept for that instance, never recomputed, no dependency list — 755; its slot is its own child cell's, at the `use`'s place, kept while the same call stands there (816, 818 (1); 771's slot allocated with the value goes) — in the root's tree of cells (824, 883)), then `use provide(c)`; `use provide(themeContext)` provides the declared default again; the value goes to everything that component renders below it — descendants only, the nearest provider wins (723, 379 (2), 354 (2)). A context's identity is its type: two contexts over one base type are two types (`type Idioma(code: string)`, `type Moeda(code: string)`) (723, 379 (5)); two same-named types of two packages are two contexts (635 → 603). No unbound read: a context whose absence is a bug says so through its default (`StyledSheet.missing()` panicking at use) (378 (3)). When the default is computed: with `comptime` written, at build, a `Run` default refused; without, by its stage; a read at build needs a default known at build (378 (2)). A read is known at build when every `createContext` that can reach it through the hooks list is of build and all give one value, or none reaches it (379 (6)). `createContext(value, Behavior)` keys a context by the behavior its value implements, the value checked at build to implement it; `use inject(Deps)` builds a record whose every field is the nearest context of its field's type, else that type's declared default, else the field's own default, else an error at build naming the field; `T` a record, a behavior refused; nothing constructed recursively (416). std's `all` is the fourth compiler-lowered hook (827). std's `Context<T>` holds `contextValue: T`, and at run time a context is its plain value (683). A context declared `#[serverOnly]` / `#[clientOnly]` restricts its readers (354 (5)); a `#[client]` island reading a context provided outside it receives the value in its payload when `T` is encodable, sealed for a server island (354 (6)). The frameworks' bases are root contexts: `rakun-bpp`'s render provides `ElementContext`, rakun's pipeline `RequestContext`, the style integration `StyledContext` (354 (7), 352). Only where there is a render tree: a decorator body, a template body and a `comptime { … }` have no tree — `use` there is refused (354 (3), 357). A `comptime` or a hole that reaches a `use` through a function it carries is refused at the `comptime`, naming the `use` and its function; a hook is a `component fn` answering `Component<R>`, read with `use`; a library function that needs a context takes it as a parameter or becomes a hook (912).

(3) **Rules of hooks.** A `use` is written once at the top level of a component body and runs on every call: refused inside an `if` / `else`, a `case` arm, a loop, a lambda, a `try` / `catch`, the right operand of `&&` / `||` / `??`, and after a statement that may `return` early — `error[use-not-top-level]` naming the construct; a condition goes inside the argument (`use provide(createContext(if (dark) darkTheme else lightTheme));`); a value sometimes absent is a `?T` the hook takes; so a body's hook list is static and a hook's slot is its position (357, 410). `use` is a keyword inside a function body only, never a module-level directive (`use client;`); `#[client]`, `#[server]` and `#[cache]` are library decorators (87). A declaration answering `Component<R>` named `use` followed by an upper-case letter is refused at its name, `hook-name-use-prefix` — a hook is read with `use`, so `use useX(…)` spells the verb twice; `rakun-bpp`'s forms hook is `use actionState(createPost, initial)` (926). `ctr:` 354 (4) has a framework's root decorator refuse a context read with no provider on its path, while 378 (3) and 723 answer the default and remove `context-unbound` — § 3 cons-2.

(4) **The hooks list.** `compiler.hooks(f)` lists every function reachable from the reflected one through calls of components — itself first, breadth-first, each once — as `HookNode(function, uses: HookUse[], calls: HookCall[], async, stage)`, `HookUse(hook, context, annotations, at)` per `use` — its type arguments (`use params<BlogParams>()` → `[BlogParams]`) each a `compiler.Info<unknown>` carrying the type's whole declaration, every field's annotations and the type's methods (726) —, `HookCall(callee, at)` per call of a component, the calls `html` generates from tags included (a `#[clientOnly]` tag generates none), and per component named as a value; a component value that comes from outside enters with `callee: null`, and the reader decides on the safe side (277, 389, 590, 576 (7)); its fields hold declaration handles (`function`, `callee`, `context`), read `compiler.name(n.function)` (590, 576 (7)); a method's or a type's node enters it (593 (3)). A component is never asynchronous because of its children: the mark counts the node's own body only (725, amending 375 (1)). A node is asynchronous when its own body writes `await` or `async { … }` (one written in a lambda of the body counts for the node), `use`s an asynchronous hook, or calls a host function answering `Async<T>` or `Component<R>`; composing another component, a value received included, only puts its lambda in the tree and marks nothing; a call through a function value or a method marks nothing, nor does a call of a botopink function answering `Async<T>` with no written `await`; a target with no published node is asynchronous (725, 504, 720). A marked component's `resolve(c, scope, key)` answers an `Async` of its tree, every other answers its tree directly (375, 725, 809 (6)). The root is always asynchronous: a `#[page]`'s render and `renderToString` await only the marked lambdas, finding out while descending whether a subtree waits — no build-time mark for a subtree (725, 504). The compiler names no stage, marker or library: `rakun-bpp`'s `#[page]` and `#[client]` read the list against the decorators they import (277, 186). The stage of a node is 376's (376 (6)). A declaration reached in the list is an opaque handle: no `value`, its meta read with `compiler.meta(h, M)` / `compiler.metaAll(h, M)` (576 (3), (8), (11), 840, 910).

Not the rule any more: a component call rendered in a component body (104, 118, 128; 791 (1)), `await c` over a component (388 (4); 791 (4)), `@Component<C, R>`'s base parameter, `@Hook`, `@Context<C>`, `@getContext(T)`, `Context<T>()`, `context-unbound`, `context-getcontext-anchor-violation` (354, 378, 269); `use context(Theme)` by type and the catalogue search (379 (1), (3) as amended by 722, 723); a component as something other than a lambda (374, 387 → 388); `component-lambda-not-lowered` (574); `component-value-to-generic` once 388's lowering landed.
