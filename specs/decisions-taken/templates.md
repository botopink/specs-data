# templates — `name @`…``, template methods and annotations, holes and types

**A template is a function whose first parameter is `syntax q: string`, called one way — its name before a raw template text `` @`…` `` —, returning an ordinary type, `anyvalue` or `anytype`; the code it answers is built, never parsed back from a string.**

(1) **The call.** The template text `` @`…` `` is a token of its own: it may span lines, holds its bytes as written — no escape sequences but `` \` `` for a backtick, no interpolation —; `${…}` and `{…}` inside it are the sub-language's own syntax, parsed by the template from its raw text; a hole's expression is spliced into the code the template answers and typed in the caller's scope — the template never reads its value (577 (1)). A template is called only as `` name @`…` `` — in run-time code or inside a tree —, `` recv.name @`…` `` (a template method, `syntax self: R` first), or as an annotation `` #[name @`…`] `` (the second `syntax` parameter the annotated declaration); `name "…"`, `name("lit")`, `name<T>(…)`, `#[name(…)]` and the template taken as a value are `syntax-call-outside-syntax` (577 (3), 578 (1)). That is the `syntax q: string` parameter's rule: a function whose `syntax` parameter has any other type takes an expression written between the parentheses of an ordinary call — `snap.matches(render(page))` with `pub fn matches(syntax value: unknown) -> anyvalue` — and is expanded at the call, its build body reading the expression through `compiler.*` and returning the code that stands there; `markup("…")` with a `syntax q: string` stays `syntax-call-outside-syntax` (719, amending 578 (1); any written return, `void` included, 841). A template declared with any other parameters is `template-signature` (577 (4)). A template function is an annotation only when its signature declares the annotated declaration as its second parameter; called as `` f @`…` `` it is `template-annotation-only`, and a template without that parameter at `` #[f @`…`] `` is `template-annotation-without-decl` — the two uses are two functions (696, 311 (2)). A template method is found by a name in the call site's scope — `` value.method @`…` `` resolves `method` as a template whose `syntax self: R` takes the receiver; a receiver's type never imports code by itself (685, 311 (3)). A template call expands wherever an expression may stand — a method body, a destructuring initializer, a lambda, an argument, a field default, a `case` arm; one left unexpanded is a compiler error, never a run-time `undefined` (425).

(2) **The return and its type.** A template returns an ordinary type `T` (the type of the code it answers), `anyvalue` (the call takes the built code's type, checked where the call stands) or `anytype` (the call is a type, built); there is no `-> syntax T` and no `-> expr` (578 (1), (2)). What a call becomes is the template's return value, a tree: any returned expression is captured and spliced as written (578 (3)). A template call's type is the type of the code it built for that call, computed at build; the signature's answer is a bound the built type must fit, an error in the template otherwise; the call unifies with the expected type as any expression — `val n: i32 = query @`…`` is `expected i32, got Array<string>` at the call; `compiler.note(message)` attaches the template's reason to the mismatch line as `— note: …`; the template never reads the expected type, so what it builds is decided by its text (426, 686). A template answering a custom tree for the language server attaches it with `compiler.custom(ast: CustomNode)` (576 (4)).

(3) **What a template body reads.** The text with `compiler.text(q)` (raw; no `Part`, no `compiler.parts` — no hole is the language's) (577 (5), 578 (5)); no hole is the language's — the template decides its syntax and reaches the caller's names through `compiler.lookup`, parsing the caller's expressions into nodes itself, never text the compiler parses back; `compiler.holes`, `compiler.isSyntax` and the `Syntax` node are gone (802); a name of the call site with `compiler.lookup(e, name) -> ?Node` — a run-time binding the name bound to it, a build value its `Lit` (a `Node` value the node itself), a `syntax` value the code it holds, spliced as written (802) —, `null` when nothing of that name is in scope, read-only (`setMeta` / `addMember` on it refused), its data meta readable at build; the read declaration's decorators run before the template body (415 (2), (3), 576 (3), 669); `compiler.bindings(e)` — only the bindings whose name appears as a word in the captured text; a `lookup` of a name that is not a word of the text is a located comptime error (237, 686; `ctr:` 577 (5) amends 237 where it reads a language hole, and the word rule still bounds `lookup` / `bindings` — 731 (5)); `compiler.source(e)` the call's `Source(file, line, col)`, `compiler.context(e)` (576 (2), 719). A template body builds a tag's handle and runs its annotation through `compiler.tagDecl` / `compiler.annotate` (636). The library decides which types an embedded expression may have: the template accepts or refuses it with a located comptime error; the compiler fixes no list (190). A template hole writes `print`'s text for every value — a record, an array, a tuple, `null`, an enum; a string writes itself; a type implementing std's `behavior Display` (27) writes its `display()`; a `bytes` hole stays refused, a `?T` hole of a `rakun-bpp` template stays an error (530, 520, 204). The code a template builds resolves each name where it was written: the library's text in the template's module, private names included, carrying their identity; the caller's holes and words at the call site; `compiler.lookup` answers the declaration and never an alias (112, 669).

(4) **Where built code is located.** Every loc-keyed plan is keyed by (expansion id, offset); a module with two alike expansions needs no padding; `query`'s `query.bp` and `rakun-bpp`'s `html.bp` drop their padding when it lands (429). An error in template-built code is located by the word it copies from the template text (the first occurrence after the previous match); a sub-language records nothing for it (691). A call inside a template expansion takes the frame of the template's use (532).

(5) **Migration.** The codemod rewrites `name "…"` / `name """…"""` / `name("lit")` / `#[name("lit")]` → `` name @`…` `` / `` #[name @`…`] `` with the string's escapes resolved to raw bytes; `-> @Expr<T>` / `-> @ExprCustom<T>` → `-> T`; `@expr(v)` → `v`; a bare type-position `type` → `anytype` (577 (6), 578 (5)).
