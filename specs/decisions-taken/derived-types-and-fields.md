# derived-types-and-fields — `Type.*`, `compiler.Field<T>` and `compiler.Info<T>`

**A derived type is an inline type named by its `val`, built by a botopink body over `compiler.fields` and `compiler.buildTypeInline`; a field's default travels with it; `compiler.Field<T>` is a build-time value with a run-time form.**

(1) **The five utilities.** `import {types.Type} from "std";` then `pub val RecipeTitle = Type.pick(Recipe, .title);`, `Type.partial(Recipe)`, `Type.omit(Recipe, .description)`, `Type.merge(Dog, Breed)`, `Type.required(T)` — statics of `Type` in `types.bp`, written in botopink over `compiler.fields(T)` and `compiler.buildTypeInline(fields)`, every parameter `comptime`, run only at compile time, no `comptime` keyword at the call (307, 599 (3), 629, 630, 628). A derived type is an inline type named by its `val` — `pub val Patch = Type.partial(Pessoa);` is `pub val Patch = type(nome: ?string, idade: ?i32, email: ?string);` —, usable in every type position, exported and imported like any type, annotatable (`#[validated] pub val RecipePatch = Type.partial(Recipe);`); there is no lineage and a spread is typed by structure: `Pessoa(..nome, idade: 3)` with `nome: Nome` accepted when the fields match, `Pessoa(..patch)` refused at the `..` because `?string` is not `string`; two structural types with the same fields are one type (629; amends 600's nominal reading and 359 (2)). An inline type bound to a `val` is named by that `val` wherever a type is named; `inline-type-outside-parameter` stays for a `type(…)` literal in a return or an annotation — the literal lives in a parameter, a record field or a `val`'s initializer (629 (2), 207, 832); an inline type may `implement` a behavior, a `val` bound to one is that type's name (645). Any function declared `-> anytype` builds a type the same way; std's five are the first of them, not a privilege; such a function has only `comptime` parameters, a run-time argument `comptime-arg-not-known`, and a `-> anytype` call anywhere but a module-level `val`'s initializer is refused at the call, `anytype-outside-type-val` (670). `derived-type-outside-val`, `derived-type-cycle`, `record-field-duplicate` hold over the built type (307, 578 (3)). A plain alias (`type Id = i32`) stays transparent (307). `Type.required` takes the `?` off each field and drops a `null` default with it (`description: ?string = null` → `description: string`); any other default stays and travels (422, 699, 671). A derived type carries the fields and their annotations only — no methods, `implement` clauses or type-level annotations of the source; the `val`'s own annotations go on the type (423, 700, 629). A generic record or an imported alias is not a source — `derived-type-source-not-record`; a local alias of a record is that record (424, 701). validation's `#[pick]`, `#[omit]`, `#[partial]`, `#[required]`, `#[extending]` are gone (307).

(2) **Defaults.** A field's default travels with the field into every derived type and resolves where it was written (669): `Type.omit(Link, .href)` in another package copies `rel = defaultRel()` with its default, the generated code calling it qualified; there is no "closed" default; `compiler.Field.defaultValue` always holds the default as written, a node bound to its module, `null` only for a field with no default; a decorator that rebuilds a type hands it on unchanged (671; amends 421). `compiler.Field<T>(name: string, type: anytype, annotations: DeclAnnotation[], defaultValue: ?anyvalue)` in `compiler.bp`: the member holds the default's code as a tree, read at build through `compiler.*` (`compiler.text(f.defaultValue!)` answers `0`, `clock.now()`), never a value computed at build — a default is evaluated where the record is built; `f.defaultValue != null` is the one test for "has a default" (598, 630).

(3) **`compiler.Field<T>`.** A build-time value: the fields of `T`'s declaration, `.field` written where a `compiler.Field<T>` is expected in a decorator's argument (`#[index(.state)]`), checked against `T`'s fields; the run-time key is gone — `Type.keys`, `Field.of`, `Field.all`, a key matched by `case` (599 (1), (2); amends 308). It has a run-time form, its constructor over the owner type and the name: a `comptime` whose value holds a field splices `Field(Book, "pages")`, which prints, compares (`≠ Field(Author, "pages")` by the owner) and keys a `Dict`, `.name` → `"pages"`; `type`, `annotations` and `defaultValue` are build members, refused in a run-time body (`` `annotations` is a build member of `Field` ``) (631). The rule from here on: a type or a value assembled at comptime is assembled by a botopink body over `compiler.*` — `compiler.fields(T)` to read, `compiler.buildType` / `buildTypeInline` to build, `addType` / `addMember` to attach — never by a compiler-side special case; `comptime/derived_types.zig` keeps only the record's materialisation and the two `val` rules (599 (3), 575 (7)). The builders take a structure, `compiler.Field<unknown>[]`, never record text (625 (3), 629 (1)); `buildType(name, fields, implements)` answers a nominal type, `buildTypeInline(fields, implements)` the structural one (629 (1), 645). B-149 owns the builders' surface and `mocks.bp`, B-140 `Type`'s bodies and `compiler.fields` (640 (1)).

(4) **Spread and derived types:** a spread copies field values by name and type from any record whose fields match the target's (629 (3)); a derived type's value is built by its own name (600 as carried); nothing of the source's behaviour travels (715) — § records-and-props.

(5) **`compiler.Info<T>`.** `compiler.typeInfo<T>(comptime t: type<T>) -> compiler.Info<T>`: the record once `TypeInfo<T>` is `compiler.Info<T>`, declared in `compiler.bp` beside `compiler.Field<T>`; both are imported where named (`import {compiler.Field} from "std";`), while `Type` and its statics stay in `types.bp`, which imports `compiler` (606 (3), 630). The type arguments of a `use` in a `HookUse` (`use params<BlogParams>()` → `[BlogParams]`) are `compiler.Info<unknown>`, each carrying the type's whole declaration — every field with its annotations and the type's methods, as `compiler.fields(d)` / `compiler.methods(d)` give them; an empty list never means "not carried"; a type is a type value, never a name string; an annotation's arguments are read through the typed meta (726, 697).
