# data-formats — `json`, `yaml`, `markdown`

**Three libraries of their own; std knows nothing of JSON; `Json` reads numbers like Jackson's strict configuration; `decode` / `encode` are the one way.**

`json` takes std's `json.bp` whole — the `Json` value type and its methods, `decode`, `encode`, `quote`, `unquote` (a JSON string literal back to its text, `quote`'s inverse), `array(items: string[])` and `object(members: #(string, string)[])` (texts already JSON joined into one, no escaping of the parts, 778) —; std's `root.bp` loses `pub mod json;` and nothing of std names JSON (`escape.scriptJson` takes a `string`); every consumer declares the dependency and imports `from "json"` (396 (1)). `json.parse` and `json.stringify` are gone; `decode` (strict: duplicate member, overflow, unpaired surrogate are `Error`, members in document order) and `encode` (document order, numbers exact) are botopink bodies, so `json` compiles on wasm under both hosts with no host (336). `Json` chooses numbers by the numeral: an integer within `i64` is `Int(value: i64)`, a larger one `BigInt(value: bigint)`, one with a fraction or an exponent `Dec(value: Decimal)`, exact; `Num(value: f64)` goes; readers `num() -> ?f64`, `i64()`, `bigint()`, `decimal()` (exact, `null` when the value does not fit — never a coercion), `isNumber()`, `isIntegral()`; `isString()` beside `isObject()`, written in std's `json.bp` until 151 s1 moves the type (941); writing keeps the value exact (332 (4)); `json` left std first, its `Json` half landing in the json repository, `Decimal` staying in std (500). `yaml` reads one YAML subset into `json`'s `Json`: mappings, sequences, scalars, flow collections; an anchor, an alias, a tag and a second document each refused with the line; rakun's `config.bp` reader was its seed and is deleted; `rakun-ssr`'s content frontmatter (onze-content's before 724) reads through it (396 (2)). `markdown` takes onze-content's (now `rakun-ssr`'s) Markdown reader and answers a tree of its own (`Heading`, `Paragraph`, `Emphasis`, `Strong`, `Code`, `CodeBlock`, `Link`, `Image`, `List`, `Quote`, …), naming no framework; `rakun-ssr`'s content maps that tree to `rakun-bpp`'s `Element` (396 (3)). A page renders a node with a component of its own through `toElementWith(doc, render)`, `render: fn(node: MdNode, kids: NodeChildren) -> ?NodeChild`, `null` keeping the default element (916).
