# backends-and-run-time-output — what every target computes and prints alike

**One computation answers or aborts alike on the four targets; std's math is bit-identical; a run-time abort prints a `Failure`, never a raw term.**

`std/math` answers the same bits on every target and OS: its transcendental functions call std's private botopink bodies (the fdlibm port) on erlang and beam too (`.Erlang(body: tanBody)`), `pow` ports glibc's algorithm as a botopink body everywhere, commonJS included — `math.pow(158.42161580281933, 2.853827476501465)` is `1896229.4525711867` everywhere —; `sqrt`, `floor`, `abs` and the other operations IEEE 754 makes exact stay host calls (259, 263). `hash.contentHash` folds code points (260). `unicode.normalize` is a botopink normalizer on the four targets (333 (A)). A prebuilt `.wasm` library merged into the emitted module, with the compiler writing the glue, is a further form "for later uses", used by nothing yet (333 (B) — withdrawn by 731 (4): `Implementation.Wasm` is 575 (6), 610, 619's enum and nothing else). `botopink run` of a program with no `fn main` refuses before running, naming the package's entry module, on commonJS, erlang, beam and wasm under both hosts (517). An uncaught run-time abort writes `<kind>: <message>` to stderr on every target; where erlang and beam abort and commonJS and wasm answer `Infinity`, the cell declares that departure, the abort's text is not one (535, 675, 444). A `crash`'s reason is the engine's (556). A value of an enum section prints as the leaf's whole path (601); a generic body that writes a `T` as text answers the same on commonJS (673); a call into a bodied, non-host generic fn of another module hands it the shapes, judged by the callee's signature alone (899); every target prints the one text (441, 521 — § strings-bytes-and-text). On commonJS a value of a generic type carries its type arguments' print shapes (`__bp_s`), written by the generic constructor from the shapes its call handed it and copied by the methods that answer a new value, read by its generic methods where they write a `K` / `V` as text — `d.display()` in another module and `print(d)` print alike (900). `@External.Beam` is gone: the beam target reads the declaration's `.Erlang` cell, `inline: true` declared by it alone (437). The beam target reads `fn:` (now `body:`) bodies through `.Erlang` (263, 437, 610). A module's production unit is the same in `build`, `run` and `test`, its tests a unit of their own (513 — § caches-and-build-outputs). Integer and float division by zero on erlang and beam raise a marked `panic` (527 (3), 675); only a binding declared outside std without `result: true` is wrapped there (546). The commonJS backend binds `i64` as 319 says; every target checks integer overflow (264, 319). On commonJS a `type` is a class per declaration and a subclass per variant, a payload-less variant a singleton — the prototype is the value's identity (5, 109); on erlang and beam a record is a tagged tuple, its tag the declaration's atom (21, 109); a `behavior` emits no module (23). The beam target lowers every Erlang construct the templates `libs/std` ships use — `receive … after`, `!`, `catch`, `try … of` / `try … after`, integer-field binary patterns, every auto-imported BIF — within OTP 28's opcode table (86, 228) and evaluates no Erlang source at run time: a template the lowering refuses is a build error at its call site, naming the function and the construct (141). `botopink run --target erlang` exits with `erl`'s status (56). botopink spells no JavaScript name (`Async`, not `Promise`); the `.d.ts` mapping is the one place JavaScript's names appear (98, 619).
