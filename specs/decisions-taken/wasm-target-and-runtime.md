# wasm-target-and-runtime — hosts, WasmGC, the hand-written runtime, std's wasm forms

**A wasm build binds to the runtime it runs on; a program's values are WasmGC's; the language's wasm runtime is hand-written `.wat`, its logic in botopink; a wasm program answers as every other target does.**

(1) **Hosts.** Two profiles built together: `wasi` — wasmtime and the runtimes that follow WASI preview 2 (`wasi:http`, `wasi:clocks`, `wasi:io/poll`), the default — and `browser` (JS imports: `fetch`, `setTimeout`, `Promise`; node runs it too); std binds a cell on both hosts or on neither, and the wasm column of every cell runs under wasmtime and under node (334 (1)); the manifest names it, `"wasm": { "host": "wasi" }` (334 (2)); `host:` only where the hosts truly differ, one adapter list for both — each `wasi:` adapter has a preview 2 implementation and a JavaScript one (334 (3), 394). What a wasm host forbids is a typed error: on `browser` a request `fetch` cannot make (a forbidden header, reading `Set-Cookie`) answers `HttpError.NotAllowedOnHost(…)`, never a header dropped in silence (335 (1)). On the browser host a call reaching `io.fs` is refused at the call, the import legal (540 (4)). A `needs` custom section hands the host only the flags the program reaches (518 (2)). The gate pins the wasmtime CLI version beside the C API's (555).

(2) **Memory and values.** The fronts of the linear-memory model are discontinued and unified in front 164 wasm-gc: B-82 the engine (wasmtime native, the page's on the web, wasm3 removed), B-83 the wasm codegen emits WasmGC for every value (`needs: [.Gc]`; no linear-memory value; a task's settled value shared, never copied; no heap per task), B-84 std-wasm rewritten (its logic in botopink, its leaves in hand-written `.wat`; `std_wasm.wasm`, `heap.zig`, the term library and `modules/beam-to-wasm/` deleted), B-85 Conformance; B-30 closed as superseded; until B-83 lands a wasm program allocates as today, a bump heap, exhaustion a trap — a known limit of a long task, written in the reference (544; amends 434, 440, 448, 449, 450, 452, 522). The program's memory is the host's collector; wasmtime does not collect cycles yet, so the codegen leaves no cycle of its own making (a settled task drops its waiters and its frame); a cycle a program builds may live until exit (555). In GC form a tuple has a GC subtype of its own, never an array's type, so a value in an `unknown` slot prints `#(1, 2)` for a tuple and `[1, 2]` for an array (568); `$__unk_eq` is structural (569). Every allocation of the linear model goes through a helper that calls `memory.grow` when the heap passes `memory.size`, a failed grow trapping (261, until B-83).

(3) **The runtime.** The language's wasm runtime is hand-written `.wat`, never Zig building `wat_ast`: printing, panic and abort, comparison, the task scheduler, `bp_ready`, the `unknown` and `Dict` helpers move to `.wat` files read by the compiler's `.wat` reader; Zig keeps only the codegen's part — the GC type table (`repr.zig`) and the choice of what a program links (WASI or `bp_host` imports by `needs`, the variants a program needs, the order) (560, 442 (3)'s rule). A hand-written `.wat` leaf names the codegen's GC types (`$str`, `$arr_any`) and never declares one — a `(type …)` in a leaf is refused at the declaration (549); a leaf may name a `wat_prelude` function (`$__wasi_random_f64`, the host's entropy) or a global (`random`'s state) without declaring it (585 (i), (j)). The Unicode case tables are data embedded with `compiler.embed` — on wasm a passive data segment read by `array.new_data`; `gen-unicode` writes data and `.bp`, never a leaf (559). Logic in botopink: `array<T>`'s members lower the `default fn` bodies `primitives.bp` holds — no `.wat` cell (585 (h)); `encoding`'s byte codecs are botopink bodies over three leaves — `bytes.length`, `bytes.at`, `bytes.ofWords` (585 (k)); `hash.contentHash` is a botopink body, every `COMPTIME REPLY` byte-equal as the oracle (585 (l)); a `string` method (641) moving to botopink is bound on wasm by a `.Wasm(body: <private fn of primitives.bp>)` cell beside its Erlang and JavaScript cells — only wasm takes the body — and moves only after 164 s2 P5 deleted the linear lowering; until then each leaf keeps its twin export (565, 566). The seeded random's stream is the runtime's (Mulberry32), bound by `std:` cells on `io/random.bp`'s `seed` / `seededFloat`; an unseeded draw calls `env.bp_random_f64`, the host's entropy, through `random.float`'s `std:random.float` cell; commonJS (`Math.random`), erlang and beam (`rand:uniform`) unchanged (451, 456). `std:` cells stay std's alone (445). The former Zig design — std-wasm's Zig transpiled into the program (440), `wat_prelude`'s split (442), the one stack `$__std_sp` (447), the heap per task (448, 449, 522, 542), the Erlang term library (450), two tables `exports` / `program` (454), `str_slice` and `mem_eq` deleted (455) — is superseded by 544, 550 and 560 where they name Zig; what survives is the rule (a helper stays in the codegen when it reads or writes the layout the codegen decides or talks to the host; it is botopink or a `.wat` leaf when it only computes over values) (442 (3), 560). `ctr:` whether a `.wat` leaf stack remains after 544 — § 3 cons-7.

(4) **Tasks and bindings on wasm:** `Async` as a state machine, the scheduler, the adapters, A-normal form before `await` — § body-markers-async-and-iter (392, 393, 394, 505); `attempt`, `defer` and exception handling — § result-and-failure (518, 597, 491); a `.Wasm` cell's forms and refusals — § host-functions (238, 481, 516, 502); a dependency function wasm cannot lower stops nothing unless reached (531); `io/clock.offsetMinutes`, `io/fs.workingDir`, `io/fs.scratchDir` have no wasm binding and stay refused on wasm; a value WASI does not define is refused, never invented (241; `io.fs` on `wasi:filesystem` is 540 (4)). `log.fileSink` answers a named `Error` on wasm, on both hosts (405). `botopink run` of a program with no `fn main` is a located error on every target and host (517). `io.http`'s `fetch` binds to `wasi:http` (334 (4), 623).

(5) **Snapshots:** a wasm codegen snapshot shows a dependency's function as one line with its hash (446, 558); the GC snapshots' `.wat` are re-recorded when every tuple construction changes, no answer moving (568).
