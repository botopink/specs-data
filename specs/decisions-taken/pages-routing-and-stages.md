# pages-routing-and-stages — `#[page]`, the render stage, request and response, islands

**The stage a page renders in is a compile-time fact read off the hooks list; no role is declared by an export's name and no segment configuration exists; a page reads its route through hooks; a route handler is always server.**

(1) **Stages.** The stages, in order: comptime (the build, where a page is prerendered) → server (request time) → client (the browser); a hook with no marker may run at any stage; a marker only restricts it; `#[serverOnly]` — the server at request time (`searchParams`, cookies, headers, a per-request query): a page that reaches one is rendered per request, the definition of a dynamic page (`D`); `#[clientOnly]` — the browser only, legal only inside a `#[client]` component; refused at compile time, at the `use`: a `#[serverOnly]` hook inside a `#[client]` component, a `#[clientOnly]` hook outside one; these two alone — 186's third, a `#[serverOnly]` hook in a page declaring itself prerendered, has no case under 202 (947); a page that reaches neither is prerendered (`S`); the build writes each route's kind (`routing`'s `k` blob, `pattern|S|D`) and rakun only reads it; `markDynamic`, `rakun_ssr.erl`'s implicit mark and every channel between them are gone (186, 277). No page declares or forces its stage: `#[page]` reads through the hooks list whether the page reaches a `#[serverOnly]` hook by `use`; no `pub val prerender`, no `output` key, no way to force a page that reaches no server hook to render per request (202). The frameworks' markers (`#[serverOnly]`, `#[clientOnly]`, `#[page]`, `#[client]`) are `rakun-bpp`'s decorators read against the hooks list, the compiler naming no stage, marker or library (277). A context declared `#[serverOnly]` / `#[clientOnly]` restricts its readers (354 (5)). A `#[page]`'s render is asynchronous at its root, awaiting only the marked lambdas and finding out while descending whether a subtree waits; a component is never asynchronous because of its children (725).

(2) **Roles and settings.** No role is declared by an export's name: the pages to prerender, the page's head, a partial page, an OG image, a content collection are said in a decorator — `#[page("blog/[slug]", paths: allPosts, head: postHead, partial: true)]`, `#[ogImage(…)]`, `#[collection(…)]` — typed; the framework never looks a function up by its name, and one left in a module is an error naming the decorator form; route file names stay the routing convention (282, 236). No segment configuration: Next's `dynamic` and `fetchCache` are gone; what remains lives in `#[page]`'s arguments beside `paths:`, `head:`, `partial:` — `revalidate: ?Duration` regenerates a prerendered page, `dynamicParams: bool = true` renders a parameter outside `paths` on demand, `headers: [#("Cache-Control", "…")]` a fixed header of an `S` page (290, 291). One routing convention: `app/blog/[slug]/page.bpp`, a `.bpp` valid where a `page.bp` is, beside `layout`, `loading` and `error`; no `pages/` tree (203). A route reaches `#[page]` as an argument — written by the author or passed by the file-convention route table the framework generates from the `app/` tree at build (`page("blog/[slug]", BlogPost)`), so a `page.bpp` writes no route (403, 285). A route file's header may import and write its kind's decorator without binding a name twice (289).

(3) **Reading the request.** A page reads its route through hooks, never a parameter: `val p = use params<BlogParams>();` — the URL's segments as a record — and `val post = use pageData<Post>();` — what `paths:` handed this path; a page function takes none (`component fn() -> View`, the marker its `use` asks, 553 (1)); both hooks are unmarked — known at build for a prerendered page, they make no page `D` (`searchParams` stays `#[serverOnly]`); `#[page]` checks over the hooks list that `P`'s fields are the pattern's segments, parsed to their types (`id: i32` — `/produto/abc` answers 404 unrendered); `route: PageContext`, `paramsOf`, `StaticPath.data: Json` are gone (293). The type arguments of a `use` (`use params<BlogParams>()` → `[BlogParams]`) reach the hooks list as `compiler.Info<unknown>`, each with every field's annotations and the type's methods as `compiler.fields(d)` / `compiler.methods(d)` give them — `fields[0].annotations` lists `#[validated]`; an empty list never means "not carried" (726). A page reads the request and writes the response through two hooks, `val req = use request();` and `val res = use response();` (`res.status(404)`, `res.header(name, value)`), both `#[serverOnly]`; status and headers are legal until the response head is written; no `isPrerendered()` — the stage is in the page's typed meta (291). Request state is atoms and cookies are typed declarations — § request-state-and-cookies (294, 295, 400).

(4) **Handlers and islands.** A route handler is always server: a `#[route]` handler (`route.bp`, answering a `Response`, every method) runs per request as if `#[serverOnly]`, is never prerendered nor exported by the build — `rakun-ssr build` writes no `<outDir>/rss.xml`; a feed that must be a static file is a page-kind file, prerendered (222, 273). Server-island props are kept secret, sealed by default: `GET /_island/Profile?p=<AES-256-GCM>`; the key is `RAKUN_SSR_KEY` (165 s2's name, 883) or one generated at build (`rakun-ssr create-key`), never a renamed key; the mode is chosen per project in `rakun-ssr.json` (`"islands": {"props": "sealed"}` or `"server"` — the props stored server-side under a random id); no `"signed"` or any mode the visitor can read; an unknown value is a config error (224, 271, 272). A `#[client]` island reading a context provided outside it receives the value in its payload when `T` is encodable, sealed for a server island (354 (6)). `rakun-ssr.json`'s keys are `trailingSlash`, `redirects`, `markdown`, `islands`, `site` (271) and `allowedRedirects`, read at build into one typed record `SsrConfig(site, trailingSlash: TrailingSlash, redirects: RedirectRule[], markdown: MarkdownOptions, islands: IslandProps, allowedRedirects: string[])` by `rakun-ssr`'s own loader: an unknown key, a wrong kind, an unknown variant or a bad value is an error at `rakun-ssr build` naming the file, the key path and the expected type, the record's defaults the one source of `--help`'s table (927). A static root's miss falls through to the routes (201 — § rakun). A navigation signal — `notFound()`, `redirect(to)`, `permanentRedirect(to)`, `redirectWithStatus(to, s)` — is `rakun-bpp`'s end to end, with a server and without: before the first chunk it is the status and headers on the generic `Response` (307 and `location`; 404 with the route's not-found boundary), after it markup the client executes (`<template data-rakun-g="redirect" data-rakun-to="…">` and `__bp2()`) with the status staying 200; a relative target must be found by `routing`'s `matchPath` in the route table, an absolute one listed in `allowedRedirects` (empty by default), anything else failing the render; the render answers `Async<Result<void, string>>`, the writers stay infallible, and rakun answers an `Error` with 500 when nothing was written, else closes, the message logged under a digest; a server action's `redirect` is rakun's, written into the `actions` envelope's `n` (115 (2), (3), 117 (1), (2), (4), 130). The signal is data the renderer reads, never a raise (527 (5), 554): `notFound()`, `redirect(url)`, `permanentRedirect(url)` and `redirectWithStatus(url, status)` answer a `Component<Element>` whose node is `NavSignal(outcome: NavOutcome)` — `routing`'s typed outcome —, a page writing `return notFound();`; the renderer, meeting the node while it descends, answers the status and headers before the first chunk and the late markup after it; no `nav:` string in code, no host raise, no `noreturn`; `signalToWire` / `signalFromWire` stay the wire spelling (924). rakun reads `rakun.*` keys only — `rakun.actions.field` / `.header` / `.bodyLimit` (1 MiB, floor 4 KiB), `rakun.appDir` — written by the orchestrator at boot (115 (4), 117 (5)).

Rows 186 and 947 are read as 979 restates them: a page's stage is read off the hooks list, `#[page]` refuses a `#[serverOnly]` hook inside a `#[client]` component and a `#[clientOnly]` hook outside one, and no third refusal exists since no page declares its stage (202).
