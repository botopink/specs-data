# functions-lambdas-and-blocks — typing, tails, `defer`, variadics, defaults

**Every function is typed where it is written; a `{` without `->` is a block and never a closure; a body's last expression written without `;` is its value.**

(1) **Typed where written.** Every function writes its return type, `-> void` included: `fn m(self: Self) -> void { … }`, `pub fn main() -> void { … }`; a `fn` with no `->` is refused at its name, `fn-return-missing`, `write -> void, or the type it answers`; no inference of a function's type from its body remains; applies to a method, a `default fn`, a `declare fn`, a static, the typed lambda `fn(x: T) -> R { … }`, a `.bpp`'s functions (622, 33; removes 06 C9 and 328's inference). A lambda `{ x -> … }` declares no types — `{ n: f64 -> n }` stays a parse error — and is legal only where its position fixes its type: the parameter it is passed to, an annotated `val`, a typed return; it may write fewer parameters than that type has, the trailing ones unnamed and given by the checker, the typed form keeping its count (888); a parameter written `_` binds nothing, any number of times — `{ _ -> v }`, `{ _, _ -> v }` —, a read of `_` unresolved, and lowers as an unnamed one does (895); a lambda nothing types is `lambda-untyped`, located (`nothing types this lambda — write fn(n: T) -> R { … } or type the val`); inference from later calls is gone (583, 328 as amended). A lambda's return is its expected type's: under `fn(x: T)` a `try` in the lambda is `effect-try-without-fallible-channel`; a lambda that can fail is written under `fn(x: T) -> Result<U, E>` (147). The typed function expression `fn(x: T, …) -> R { … }` is legal in every position — a `val`, a `var`, an argument, a return, `addMember` —, every parameter typed or none; where the position has a type the written types are checked against it (408). A free type variable as the expected return accepts the typed forms' own marker, and an expected type that is no function type is left to ordinary unification — both as built until B-116 P4's codemod has run, then refused (712).

(2) **Tails and blocks.** A body's last expression written without `;` is its value — a named `fn`, a method, a `fn` expression, a lambda: `fn inc(x: i32) -> i32 { x + 1 }`; with `;` it is a statement and a `-> R` body then needs a `return`; a valued tail or a valued `return` in a `-> void` body is refused at it; an early `return` stays; a braced block statement at the end (`if` / `case` / loop) is not the tail; the formatter neither adds nor removes the tail's missing `;` (409, 622, 541 (1)). A `{` followed by parameters and `->` (or `->` alone) is a lambda; a `{` without `->` is a block — a scope, never a closure; a trailing lambda with no parameter writes `f(x) { -> … }`; `@block` is removed; a block used as a value answers its last expression written without `;` — a bare `{ … }`, a `case` arm `p { … }`, `comptime { … }`, `async { … }` alike; a `return` in a block leaves the enclosing function, a `return` in `async { … }` leaves the `async` block; a `var` reassigned in a block is a plain reassignment; a block handed where a function is expected is refused with the hint "missing `->`?"; a block whose value is `void` handed where `unknown` is expected is refused (525). `await`, `yield`, `break` / `continue` to an outer loop inside a block reach the enclosing function or loop; a `case` arm's `break <value>` is removed, the arm's value its tail; a block as the last statement of a function body is its tail (541 (2)–(4)). `if` is not an operand, parentheses included: `val x = if (c) { a } else { b };` (159). A braced `if`, loop or `case` statement ends at its `}` (29); the `;` after it is accepted by the parser and removed by the formatter (524, 60); a braceless statement keeps its `;` (60).

(3) **`defer`.** `defer <expr>;` runs `<expr>` when the block it is written in ends — block scope, as Zig and Swift —; several run in reverse order; it runs on every exit (the end, `return`, `break`, `continue`, a propagating `try`, a `throw`, a panic `attempt` catches); in an `async` body when the task's body ends, after its awaits; in an `AsyncIter` when the stream ends or its consumer stops; its body cannot leave the path (`return`, `break` / `continue` out of it, `yield`, `await` refused) nor fail — a `throw` is `defer-throw`, a `try` propagating out of the body `defer-try`, a `try … catch` region inside it handled there; a `Closeable`'s `close` answers `void` and cannot fail (800), so `defer x.close()` is always admitted (866, 883); the deferred expression is evaluated when it runs, not when `defer` is written (`var f = open("a"); defer f.close(); f = open("b");` closes `b`), and a `return <expr>`'s value is computed before the block's defers run; no resource check: a `Closeable` value not closed compiles; std declares `pub behavior Closeable { fn close(self: Self); }`, known to no compiler rule (539). A `defer` always runs on every target, whatever goes wrong: a function holding one adds `.exceptions` to the program's `needs`; `defer f.close(); print("x"); panic("y")` answers `x`, runs `f.close()`, then aborts (597).

(4) **Parameters.** A variadic parameter is spelled by the declaration, `..values: unknown[]` — only the last parameter, at most one, its type an array, no default and no label; a call passes zero or more positional arguments after the fixed ones; no spread at the call site (an existing array is passed by declaring `values: T[]`); commonJS a rest parameter, erlang / beam one list, wasm one array (267). A default is trailing everywhere — free `fn`, method, record fields and variant payload alike, decorators included (`fn-param-default-trailing-only`) (244, 406). A second binding of one name in one body is `binding-redeclared` at the second, naming the first, parameters included, reaching every block and every `case` arm; two sibling blocks may each bind the same name; no target invents a scope (152, 205). A plain function call takes no spread; a record constructor does (359, 529 — § records-and-props). An integer literal past its type's range is refused by the checker (319). Assigning to a `val`, local or module-level, is a located error naming `var` (38).

(5) **Precedence.** `await` and `try` are prefix operators binding as the unary `-` does (`await t * 2` is `(await t) * 2`); postfix (`.`, `()`, `[]`) binds tighter (`await t.x` is `await (t.x)`); `catch` is the infix of the lowest precedence, below `||` and every other operator; `??` is the tightest binary level (28, 330, 537, 865), its left side the whole expression before it; parentheses group as anywhere (537). `??` beside `&&` / `||` without parentheses is a compile error (330 (4)). A type name with explicit type arguments followed by `.member` or `(` is a type application (`Dict<string, unknown>.empty()`); elsewhere `<` is a comparison (255 (1)). A call's result may be called (`adder(3)(4)`), a parenthesised expression takes a member (`(a == b).toString()`), and any type takes `[]` — `#(a: i32, b: string)[]`, `Result<…>[]`, `(i32 | string)[]` (28, 14).

(6) **Loops.** `loop`, `while` and `for` are statements (`void`), one meaning each — `loop { … }` repeats until `break`, `while (cond)` while its condition holds, `for xs { x -> … }` (or `for (xs) { x -> … }`, the parentheses optional with one source) over a collection, a range or an iterator, `for await s { x -> … }` over an `AsyncIter`, the source `try xs` where the iterator's end is a `Result` (553 (3)); several sources walk together, `for (a, b) { x, y -> … }`, the parentheses required, one parameter per source, ending with the shortest — an open range `0...` the index, `for (0..., g.iter()) { i, item -> … }` —; the body a loop body, not a lambda; `for x in xs` is refused `for-in-loop` (105, 956, reversing 950) —; `continue` exists in all three; a label follows the keyword, named by `break :outer` / `continue :outer`; a `break` with a value, `yield` and a collecting loop exist only in the `iter` / `async iter` forms of § body-markers-async-and-iter (105, 584, 553).
