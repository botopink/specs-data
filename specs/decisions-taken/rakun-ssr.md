# rakun-ssr — the orchestrator

onze's (now `rakun-ssr`'s) `@/` alias is gone: an application writes `import {lib.db.findPost};`; staging no longer rewrites `from "@/…"`, which is `module-import-with-from` like any other (218). `chainFor(patterns)` keeps taking the ancestor patterns rakun's layout chain names — `rakun-ssr` derives no chain of its own — and `rakun-ssr` consumes `routing.conventions` for what an app file is (`conventions.fileKinds` / `conventions.classify`), importing `routing` (323). `RakunSsr.run` (893) registers `public/` at `/**` before the routes (201). onze and its eight members are now the workspace package `rakun-ssr` of `botopink/rakun`, their history kept by `git subtree add` and the repository archived (724, overtaking 507's `repository/onze` on tag `mocking-lib-final`, the mocking library kept as that tagged history). `rakun-ssr` uses the `cli` library: `start` spawns the node with `forwardSignals()`, `create` asks through `cli.prompt` on a terminal (506 (3)). `rakun-ssr`'s content (onze-content before 724) reads its frontmatter through `yaml` and its Markdown through `markdown` (396). `rakun-ssr`'s release `text_…` and `dockerfile_…` (onze-release's before 724) are the milestone's only new snapshots (390 (3)). The og module refuses a malformed integer: `parseMetrics(family, weight, text) -> Result<FontMetrics, string>` answers `Error("<family> <weight>: line <n>: \"9x0\" is not an integer")` and `gradientOf` answers its not-a-gradient value for a non-integer angle — never `0` (942). `rakun-ssr.json`'s keys and the island modes are § pages-routing-and-stages (271, 272, 224). Track 07's choices stand under the names (955): the core's suites render through their own `describe*` and write through `snap`'s `assertAs`; `rakun-ssr.json` refuses an unknown key, a duplicate, a wrong kind, a port outside `1..65535`, a non-string `allowedRedirects` entry; the boot's rakun half is `rakun-ssr-server`; `build` stages `ssr_main.bp` and compiles it to BEAM, `start` spawns the node with `forwardSignals()` and runs the release's `bin/rakun-ssr` when it exists, the one start path; the font-metrics table has five transcribed rows, its generator owed; the blog's sources sit under `src/` (`appDir: "src/app"`); a client-manifest field escapes `%`, `\|`, LF and CR only; the `stylesheet-hash-split` / `stylesheet-unevaluated` probe holds until the tag annotation's tokens are comptime; `rakun-ssr` keeps `AssetRoot` and `rakun-ssr-server` converts it to `rakun-service`'s `StaticRoot`. A value the browser may see is declared once, marked where it is read — `#[publicEnv] pub val apiUrl = env.read("API_URL");`, `rakun-ssr`'s decorator on a `val` recording `PublicEnv(name)` —: the bundler inlines the build's value of each marked `val` into the client bundle and refuses, located, every `env.read` a `#[client]` component reaches that is not such a `val` (`env-non-public`, naming the marker); the `RAKUN_SSR_PUBLIC_` (formerly `ONZE_PUBLIC_`) prefix is gone, nothing carried by a variable's name (928).

(dev) **The dev loop.** `rakun-ssr dev` is `build` then `start` over a file watcher (std's `fs` mtimes; the child spawned with `forwardSignals`): the node restarts on every change and serves the bytes `start` serves; hot-loading is not a form of the loop on any target — the server exists on erlang alone, a reload is a restart on commonJS and wasm by construction, and on the BEAM a swap leaves state `start` never has (766, 67). `botopink build` materialises the dependencies' cached `.beam` into the output and `compileBeam` compiles only the app's own `.erl` (767, 509 (4)). Island state is lost on every edit.

955 is read as 965 restates it: 68-a's client manifest carries no public-env prefix — the environment values a client bundle may see are the `#[publicEnv]` `val`s alone (928).
