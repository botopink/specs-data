# records-and-props — construction, spread, a component's props

**A record constructor evaluates its arguments in written order; `..` is the one spelling of the rest; a spread copies field values only, typed by structure; a component's props are plain parameters or one record parameter.**

(1) **Spread.** `val pessoa = Pessoa(..pessoaOld, nome: "Ana");` — `..src` at the start of an argument of a record constructor; `...` is only the inclusive range `a...b`; `...` as a spread is refused naming `..`, nothing migrates it (529 (3), 864). A spread copies fields by name and type, from any record whose fields match the target's — `Pessoa(..patch)` refused at the `..` because `?string` is not `string`; two structural types with the same fields are one type (629 (3); replaces 359 (2)'s "derived by 307"). Arguments apply left to right, the later winning; several spreads and labelled fields mix; a field written explicitly twice is an error (359 (3)). Every field without a default must be supplied; a missing field is an error at the call (359 (4)). A record constructor's arguments are evaluated in the order written, a spread's source included, each once — `Pessoa(nome: say("n"), ..make())` prints `n` then `make`; the copy is of the values only: the new record's methods are its type's, nothing of the source's behaviour travels (715, 359 (6)). A plain function call takes no spread (359, 529 (2)). A record is immutable: a field assignment `p.f = v` is refused, located, naming the update form `Person(..p, age: 31)` — so `val` protects the value as well as the binding, and identity is unobservable (37, 35).

(2) **Props.** A component may take its props as ordinary parameters — `pub fn Card(title: string, featured: bool = false) -> View` — and a tag passes each attribute as the labelled argument of that name (`<Card title="Olá" featured />`); an attribute naming no parameter, or of the wrong type, is a build error at the attribute (529 (1)); or as one record parameter `..props: R`, `R`'s fields the function's parameters from outside, the body reading the record `props`; at most one per function; a spread (`Card(..p, featured: true)`, `<Card {..p} featured />`) is legal only into a record parameter (529 (2)).. A method and an associated function take `..props: R` as a function does; beside it no variadic and no default; a generic `R` is typed by the call (864). A `.bpp` with `type Props(…)` unfolds to `pub default fn (..props: Props) -> View` (529 (5)). A component's attributes are the fields of its props; an undeclared attribute, a value of another type and a field with no default left unwritten are comptime errors at the attribute (192); a component's content is its default slot, read with `<Slot />` — no `children` field (193, 360). Both forms stand (737): plain parameters or one record parameter, 529 (1), (2) whole; 593 (2)'s "one record parameter, never a list" and its refusal of a second parameter are gone, a type's fields staying its props.

(3) **A type as a component.** A type implementing `Composable<R>` is a component: its fields are the props, its `component fn compose(self: Self) -> Composition<R>` the body, where the component starts — an agnostic name, for a view, a style, a service or a hook alike (804 (1), 809 (2)); `X(fields…)` answers an `X`, a `Component<R>`; hooks only in `compose`; refused: `implement Component` (`implement-component-not-composable`), a `compose` with no `component` marker (`component-compose-unmarked`), a missing or differing `compose` (58, 800), a `Scope` field (`component-scope-field`), a `use` outside `compose` (`use-without-component`), `X.compose()` outside std's `resolve` (`component-compose-called`), a `T` that is a component or an `Async` (`component-arg-is-component`) (593 (2), 804 (1), 809, 828); a field is read as `self.title`.

(4) **Opaque types.** `[pub] opaque type X(…) { … }` — the modifier before `type` —: `X(…)` is written only inside `X`'s own methods (`opaque-construction` elsewhere) and its fields are read only there (`opaque-field`); outside, an `X` is named, passed, stored, compared and tested with `is`, never built nor opened; the constructor and the fields are private to the type — not to the rest of its module — while a method without `pub` is private to the module, as any declaration without `pub` is — of every type, `method-not-pub` at a call from another module, a method implementing a behavior's member reached through the behavior (an extension block of another module meets it only `pub`, 886), the lowering by its mark (814, 830, 859); the `.d.ts` declares a type's `pub` methods and, with them, every method without `pub` that implements a member of a behavior the type's own `implement` clause names — what another module may call — and no extension block's (894); `opaque` closes a record alone — before an enum, a namespace type, a primitive type or an alias it is `opaque-not-record`, and a pattern over an opaque type's fields is `opaque-field` (829). std's `Scope` and `Module` (`mod.name()`, `mod.path()`) are opaque; `Composition<T>` is not, a function type (815) (811). A method, a lambda or a `default fn` answering `Component<R>` lowers as a top-level component (593 (1)).
