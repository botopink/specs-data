# conformance-suite — cells, the `.snap` format, the reference and the decision cells

**A cell is a directory with one target-independent answer per module and per-target departures; every reference example is a cell; the expected answer is the language's, never the compiler's; no check ever accepts a snapshot.**

(1) A cell: layout, manifest, no generated code, external services, beam as a target — 457, 160, 8.

(2) The `.snap` records and their order: `build`, `refused` / `at` / `label` / `from` — 789, 868, 904.

(3) The CLI `botopink cell` (new, check, candidates, never accepts) and the in-process suite and library test that replace the check — 464, 989, 993.

(4) The reference beside its cells; fences, markers and links — 134, 157, 461, 462, 463, 548, 650.

(5) Proving a front: the Conformance step, the in-tree pattern — 458, 459, 465, 466, 467, 480.

(6) Decision cells, the ledger's `Cell` column and the two ledger files — 646, 647, 648, 649, 651, 730, 750, 775, 776.

(7) Consolidation into modules and cases, who runs conformance — 760, 761, 765, 768, 773, 779, 781, 796, 860.

(8) The build modes, the `.bpr`, `--emit-resolved` and its printing — 798, 805, 834, 836, 837, 838, 902, 971.
