# conformance-suite — cells, the `.snap` format, the reference and the decision cells

**A language cell is a directory with one target-independent answer per module and per-target departures; every example of the reference is a cell; a cell's expected answer is the language's, never the compiler's; `botopink cell` never accepts a snapshot.**

(1) **A cell.** `repository/botopink-lang/conformance/modules/<cell>/`: `botopink.json` (a project like any other, its `name` the directory's, `"targets"` when narrowed), `src/<module>.bp` (always `src/main.bp`), `snapshot/output/<module>.snap` — the answer the language gives, one for every target: the program's output and that it aborts in `main.snap`, a module's refusal (message and `line:col`) in that module's `.snap` —, `snapshot/targets/<target>/<module>.snap` only where a target departs (it refuses that module for a host binding it lacks, or names an abort in its runtime's words), `docs.md` (457, 475 (1), 511). The 1,650 cells are being consolidated into fewer modules, nothing tested lost — grouped by subject, a cell that must stand alone (a refusal, an abort, a narrowed `"targets"`) one compilation unit of a module holding several, each with its own snapshot, the old → new mapping generated and every reference rewritten by it, counts equal before and after, after the group's codemods; the format is the step's plan (760, B-157) — and the consolidated home is 166's tree: `modules/decisions-taken/<slug>-<N>/`, each decision's directory holding the cells that prove it as its cases (an existing cell moves under the decision its `Cell` column names; a cell proving no decision stays outside, by subject), one directory per decision still check 7's contract (761). The format (765, amended by 779): a module packs its cases into two packages — `<module>/run/`, every case that prints, `src/cases/<case>/mod.bp` each with its entry `pub fn run()`, called in order by the package's `src/main.bp`, answering in one `snapshot/output/main.snap` of the cases' `out` lines in call order, and `<module>/refused/`, every case the compiler refuses, one build answering each case module's refusal in `snapshot/output/cases/<case>/mod.snap` — and keeps as a full cell under `<module>/cells/<case>/` a case that cannot share a package (an abort, a narrowed `"targets"`, a dependency, a departure, an asset, a lone case); a case packs only when `cell check` of its package equals its old answers on every target, so no answer is regenerated (`scripts/pack-cells.py`); one compilation and one runtime start per package, not per case (779); once `compiler.load` lands (780), `run/` and `refused/` become one package per module, a refused case a file the package does not declare, read by `main` through `comptime compiler.load(…)`, whose answer `snap.matchesRefused` records as the case's old refusal records in a test of the package run by `botopink test` (784) (`refused …`, `at …`, `label …`), so each case proves the same refusal at the same place; what `load` cannot answer, and every running answer, stays a cell (781, 782, 784); the `.snap` format untouched; a cell citing several rows lives under the highest-numbered one in force, linked from the others; cells proving no decision under `modules/<prefix>/cases/<cell>/`; a moved cell keeps its name; the 817 reference markers get their path rewritten only; a row no cell proves gets a `draft/main.bp` stub; one commit per prefix group, largest first; the moves run before machine 1's codemods, which operate by glob, every branch touching a cell rebased after them (773). No generated code in a cell: JavaScript, Erlang, BEAM and WAT text stay compiler-core's snapshots (457 (3)). `test/` suites keep `botopink test --json`; a `test/` suite that narrows its targets is a directory with a manifest (457 (2), 536). A departure never records a compiler defect: a wrong answer on a target is a 144 row, the cell red or out (458). A cell that needs an external service asserts against an in-process double; a cell that prints "skipped" has not passed (160).

(2) **The `.snap` format.** `botopink-cell 1` on line 1, one record per line, in a fixed order, written and read in one place (`cell_snap.zig`): `out <text>` (a bare `out` an empty line), `no-final-newline`, `abort` (the exit status never pinned), `stderr <text>` (after `abort` only; a containment claim), `refused <message>` / `at <file>:<line>:<column>`, `label <text>` (475 (2), 485), `from <file>:<line>:<column>` after `at` and `label`, one per `called from` line, innermost first (532, 868); a refusal and program output never share a file; a header alone is the empty answer; a departure replaces the module's whole `output/` answer on that target; a module's snapshot is named after its source; a refusal with no location is `main`'s; a majority is strictly more than half the targets; an empty answer is never accepted by default (475). A refusal prints `error[<code>]: <message>` (557); a `crash` cell claims `stderr crash:` alone (556).

(3) **`botopink cell`.** `cell new <path>` scaffolds a cell; `cell check <cell|directory>` compiles and runs each cell on every target it declares — beam executed through `erlc +from_asm` and `erl` (8) — and compares: equal → exit 0; different → a `<file>.snap.new` candidate beside it, exit 1 — the accepted snapshot is never overwritten; a new cell gets candidates (every target agreeing → `output/…snap.new`; a target departing → `output/` from the majority and `targets/<t>/…snap.new`; no clear majority → one candidate per target, the choice a person's); no update flag — a person accepts by renaming (464). One implementation in `compiler-cli`, run by the in-process runner, the pipeline's `cells` job and the libraries' gate stage (464 (5)).

(4) **The reference.** Every example in the language reference is a cell: `conformance/docs.md` holds the index and the text no single cell owns, `conformance/modules/<cell>/docs.md` the text for what that cell shows; botopink-lang's `docs.md` and `docs/` moved there, the manifest schema with them, no copy (461, 462, 466). A `docs.md` includes code by an ordinary Markdown relative link — `[src/main.bp](src/main.bp)`, `[fn_tail_value](modules/fn_tail_value/src/main.bp)` —, never a `{…}` placeholder or an HTML comment (the root reference keeps its `<!-- example: … -->` markers until 166 s4's codemod rewrites them to links, 650); the renderer expands a link whose target is a `.bp` file into the code block, and `test-docs` and meta check 7 hold every target to an existing file (650; amends 461 (2) and 548 (3)). Each library's reference and examples live in `<lib>/conformance/`, in the same shape; rakun's is one suite read by feature, each feature's `docs.md` beside its cells, a package's `docs.md` its map (463, 548). `docs-check: skip` is gone; `reject <error-id>` and `project` fences replace it; a table or a grammar is not fenced as `botopink` (157).

(5) **Proving a front.** A front that changes botopink-lang proves itself in the suite: a cell is never edited to match the compiler, and an example the compiler does not yet accept for a reason the language intends is a compiler gap to close, not an example to weaken (134); the behaviour a change adds, changes or refuses is measured against the cells that cover it and the cells it calls for are written, red on the base and green on the tip; a change of observable behaviour with no new or changed cell is not done (458). Every such front ends with a "Conformance" step after its other steps landed: the whole suite green on every target, read from `feat`'s pipeline; the front's changes analysed against the cells; the missing cells proposed; the reference updated (459, 480); a library front ends the same way, `botopink cell check conformance/` over `<lib>/conformance/` (465). A reference text that contradicts a cell's answer is a red of the step (480). The `botopink/conformance` repository is deleted (467).

(6) **Decision cells.** The steps file's table (730) has a fifth column, `Cell`, the slug of the row's decision cell, empty for a one-liner or a `process` row; the slug is chosen where the decision is written (647). A decision cell's directory is `conformance/modules/decisions-taken/<slug>-<N>/` — the slug, a hyphen, the number — holding a `docs.md` whose first line is generated (`# Decision 622 — …`) and the program (646, 648). In phase 1 the example is `draft/main.bp` with no `src/`, and `draft/botopink.json` (with `draft/deps/<pkg>/` when a dependency is needed) where the rule is the manifest's, a `.bpp`'s or a dependency's — `compile` reads it, `promote` merges it into the case's manifest (775); so `cell check` sees no cell; `scripts/decision-cells.py compile` builds each draft in a scratch package; `promote` moves `draft/` to `src/`, writes the manifest and adds the glob; the two moments told apart by the tree's shape, never a flag (649). The subtree `conformance/modules/decisions-taken/**` of every repository belongs to front 166, its threads committing there directly, one per repository, nothing outside the subtree — the one carve-out of 433, "for now" (651). `decision-cells.py compile` keeps each failing draft's error — the first diagnostic line per target under its `FAIL` line, the whole output with `--verbose` (750). Meta check 7 is § gate-and-ci.

(7) **The build phase and the module package.** `cell check` records the build phase before the run: `build <text>` per line a build body prints, before the package's own refusal records — a build prints, then refuses; a refusal at analysis has none before it; a `build` after a `refused` is malformed (904, amending 789 (1)'s list) — and before `out`; `botopink build` / `run` print the program's build output to stdout and their own messages to stderr; the build lines are one answer for every target, a target that differs a defect (789 (1)–(3)); the CLI's `cell check` records no `build` line — the program of 790 writes them, the CLI only keeping its messages off stdout (796). A conformance module is one package — `src/main.bp`, `src/cases/<case>/mod.bp`, `snapshot/output/main.snap` —: `main.bp`'s `runCase(comptime name)` prints `== <name> comptime`, loads the case with `try comptime compiler.load(…) catch { r -> … }`, and registers a `compiler.init` that prints `== <name>` and then the refusals as `refused error: …` / `at …` / `label …` lines or the case's run (`try mod.run() catch { f -> print("abort …") }`); a top-level `comptime { runCase("<case>"); … }` calls it per case (788); `run/`, `refused/` and the per-case `.snap` are gone, and the suite depends on no `snap` (789 (4)–(6), amending 781 and 784). `cell check` becomes a botopink program, `conformance/check/` on commonJS, spawning `botopink build` / `run` through `io.process`, building the records from the console, comparing and writing `.new`; it replaces the CLI's command once its snapshots equal the CLI's over the whole suite (790). The build runs comptime once and answers a resolved program — botopink with no comptime left — from which every target is generated, so the build phase is one answer for every target by construction; comptime never reads the target. `botopink build --target <t>` goes straight to the target (the default); `--emit-runtime <dir>` writes `<dir>/<pkg>.bpr` per package — the resolved tree in the compiler's own binary format, uncompressed, a dependency's file reused by every dependant, recording the compiler that wrote it (another compiler refuses it: run the build again) — one file per package and per std module reached (`<dir>/std/<module path>.bpr`, level B's filing), the root's file alone carrying the program's order, its module table and the wasm host, a dependency's file refused as a program (`runtime-not-a-program`) (837) —, which `build` / `run` compile to any target later with no comptime, `--target` required (805 (1)–(3)); a `.bpr` is built and run from the directory of the project that wrote it — its host files are that directory's, the file holding paths relative to the package and no directory — and refused from another, `runtime-other-project`, when the working directory's manifest is missing or names another package (838); `--emit-resolved <dir>` writes the readable `.bp` — a host template kept as an annotation, one file per module, `<dir>/<pkg>/<module path>.bp`, the modules grouped as the `.bpr` groups them, every name as written and the imports kept (834), a specialised copy's own name `name_$N` between backticks (561) — with comments naming each piece's origin, for reading only (805 (5)); `// from <template> (file:line)` for a template expansion, `// from comptime (file:line)` for a folded value, `// from comptime { … } (file:line)` for a top-level block, beside 798 (2)'s `// from #[controller] (file:line)` (902); a folded value with no literal is printed as the call that builds it — `createContext(v)`, `Asset(Link(path: "…"))`, `bytes.fromHex("…")` (885); `$` and the prefixes `__bp_` / `Bp__` in a hand-written name are refused, `reserved-name` (805 (6)); the compiler's own twin, section and embed names live there too (`__bp_<f>__type`, `Bp__<Enum>__<Section>`, `__bp_embed_<p>`), an associated type keeping `<Type>__<Assoc>` (836); the directory is required, the files written named; a target built directly and from the intermediate answer byte for byte the same. `cell check`'s program builds each package once with `--json --emit-runtime` (JSON lines: targets, build prints, refusals, the intermediate's path, a summary) and runs every target from the intermediate, `--cache-root` and `io.process.start`'s `cwd` / `env` with it, no shell; the intermediate is no snapshot (798).

The suite checks itself in-process: each module's `main` loads its cases with `compiler.load`, `run()` answers the printed text (`.Refused` / `.Excluded` on a target-only answer), compares with one sectioned `main.snap` and writes `.new`; no spawning program, no CLI `cell check` (989).

The gate's library check runs in-process: a botopink program loads every library and workspace member with `compiler.load(package: …)`, runs `Module.test()` (a `TestReport` per package) on the four targets, every exclusion audited by the compiler; `botopink-lib-test` leaves (993).
