# stages-and-folding — `Build`, `Run`, `Any`, and what is computed at build

**Every function has a stage computed from the resources it names; what depends on nothing of the run time is computed at build wherever it is written, fully or an error at build.**

(1) **Resources and propagation.** Build-only: `compiler` itself — `compiler.*`, a template body's reads (376 (1), 634 → 575 (3)). Run-only: a host function with an effect (io, `fs`, clock, random, network, `process`, `env`), an `await` on a host `Async`, a module `var` (376 (1), 547 (iv)). Neither: arithmetic, strings, records, arrays, `case`, loops, std's pure primitives — `Any` (376 (1)). `Any + Any = Any`, `Any + Build = Build`, `Any + Run = Run`; `Build + Run` is `build-and-run` at the second resource, naming the first; a `comptime { … }` block inside a `Run` function is resolved at build into a constant (376 (2)). Host functions are `Run` by default; std declares `Any` on its pure primitives (376 (4)); a function's stage is written only as `#[stage(.Any)]`, `stage` imported from the std module that owns it; `Build` and `Run` are never written — `#[stage(.Build)]` / `#[stage(.Run)]` refused by `stage` itself (681, 663). `use` is a means, not a stage: `use h(…)` has `h`'s stage — `provide` and `context` are `Any`, `request()` / `response()` / an atom `Run` (376 (3)). A body that runs at build calls `Build` and `Any` functions, never a `Run` one — `run-in-build` at the call (376 (5)). A call's stage is the called declaration's, and only what is written at the call counts — a call through a function value, a method on a value, a lambda received add nothing; `val f = clock.now; f()` passes the checker and is refused when the build executes it and reaches `clock.now`, the build's runtime raising `run-in-build` at that call, located (720). In a function whose every parameter is `comptime`, reading one no longer makes it `Build`; it makes it expanded (562, amends 376 (1)). The stage is published with the hooks list (`HookNode.stage`) (376 (6), 277).

(2) **Folding.** An expression whose every input is known at build (a literal, a constant `val` of any module, a `comptime` value, a context read known at build) and whose every function is `Any` is computed by the comptime runtime wherever it is written — a body, an argument, a hole, a `val` —, no `comptime` needed: `val raio = ESPACO * 2 + 4;` inside a component is `12`; `padAll(n)` with `n` a parameter is not (380 (1)); a `Build` read in a run-time body is written under `comptime` — `compiler` there without it is `compiler-at-run-time` (575 (3), 606 (3), 607 (1), 634). An `Any` function that writes no `panic` / `throw`, no `print`, no module `var`, no function-value call and no method of a declared type folds, and its calls through other such functions fold too (682); `print` is an effect and never folds (632). No limit: what runs at build runs to its end — no step or time budget, no fallback to the run time; a computation that never ends never ends the build (380 (2)). Every raise met while folding is a build error at the expression — a failed conversion, a missing key, a `panic` reached inside an `Any` function; an index out of bounds is no raise, `xs[3]` answering `null` (777) —, the message the target would print; this lands after the comptime runtime's primitives answer exactly as the targets do (721, 380 (2)). A raise written as such — `panic(…)`, `throw` — is never computed at build unless `comptime` is written: a dead branch's `panic("never happens")` stays a run-time raise (380 (3)). `comptime` written demands the build: an input of the run time under it is an error at the input (380 (4)). A template's hole known at build whose fold raises is refused at the hole, located, never deferred to render (911).

(3) **Arithmetic at build.** An arithmetic error at build reads as Erlang's, located as JavaScript's: `` error: comptime-badarith: an error occurred when evaluating an arithmetic expression — `1.0 / 0.0` (division by zero) `` with ` --> src/main.bp:<line>:<column>` (472); every division and remainder by zero — `/` and `%`, integer and float, alone or inside a larger expression — reads `… (division by zero)`, located at the operator that divides (533), its backticked text that dividing operation as written, never the whole expression (869). Structural equality at build answers whatever the depth — iterative, never bounded by the runtime's stack; a depth limit is never part of the language's answer (471). A raise at build is located at the call that raised, in its own file, every call of the chain a `called from <file>:<line>:<column>` line, innermost first, down to the program's call, annotation or `comptime`; a call inside a template expansion takes the frame of the template's use (532).

(4) **Components at build:** a component may be called at build — in a `comptime` block, a template, a module `val` known at build — when its stage is `Build` or `Any`: it runs on the comptime runtime with `Scope.root()` (809 (8)), its contexts answering their providers within the tree or their defaults; one reaching a `Run` hook is `run-in-build` at the call (378 (4), 388 (4), 594 (1)). A `styled` literal is computed at build when every hole is known at build, at render only when a hole is not (355, 377 — § styling).

(5) **Top-level `comptime` blocks.** A module may hold `comptime { … }` blocks — build bodies run once per build in the order written, after the module's declarations are known: `compiler.*`, `val`s known at build, calls of functions expanded at build (a function whose every parameter is `comptime`, 562 — no `comptime fn` form), `print`; a run-time effect there is `run-in-build`; each `compiler.init` registered there runs at program start in that order; a `print` reached there is the build phase's output, recorded as `build` (788, 789, 796). A `return` or a `throw` in a block is refused; a library's blocks run in the build of the package that uses it, in 660's level order; a `pub` function whose every parameter is `comptime` is expanded also when another module's block calls it; a cached build replays the build output; a `comptime { … }` inside a function body prints build output too (793). Such a function is expanded at build wherever it is called — a `comptime` block, `main` or any run-time body, a `comptime { … }` inside a function — and in its own module it type-checks with `compiler.init` typed `void` and leaves the program; its `compiler.init` becomes a program-start init only in a top-level block, and anywhere else the executor's body is written where the call is, run when that line runs; a call from a decorator body stays refused `compiler-output-outside-decorator` (808).
