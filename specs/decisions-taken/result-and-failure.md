# result-and-failure — `Result<T, E>`, `try` / `catch` / `throw`, `attempt` and `Failure`

**`Result<T, E>` is botopink's checked error; `try` opens a region that `catch` closes; a failure is always a `Result` in the value's layer; a crash is contained by `attempt` alone, its `Failure` kind exact on every target.**

(1) **Checked.** `throw` and the propagating `try` need a `Result` in some layer of the return — `effect-try-without-fallible-channel`, its message naming `try … catch` and a binding's `result: true`; every call that may fail writes its `try` — no implicit propagation (`val x = try f();` propagates, `val r = f();` is a plain `Result`) (431 (1)). `Ok(…)` / `Error(…)` are never constructors in an expression: a `Result` is made only by `return v` or `throw e`; `Ok` / `Error` in an expression stay `unbound variable` (208). A failure is a `Result` in the value's layer on every type: `Result<T, E>`; `Async<Result<T, E>>`; `Iter<T, Result<V, E>>` / `AsyncIter<T, Result<V, E>>` — a `throw` or a propagating `try` ends the iteration with `Error(e)`, the items bare `T`, consumed by `for try xs { x -> … }` / `for await try xs { x -> … }` (956); `Component<Result<R, E>>` — a component throws only under it, the `Error` reaching the nearest `ErrorBoundary`; `return v` is `Ok(v)` where the layer is a `Result`; `Iter<Result<T, E>>` stays an iterator of results; `Result` needs no marker (553 (3)). `?T` is read with TypeScript's operators and has no methods: `??`, `?.`, `?.[i]`, `?.(args)` and the postfix `!` are the whole surface; `map`, `flatMap`, `unwrapOr` stay on `Result` (`r.map(f)`, `r.flatMap(f)`, `r.unwrapOr(x)`, `r.isOk()`, `r.isError()`, the one spelling; the builtin `result` namespace is gone); an operator over a value that is never `null` is a compile error; `?.` flattens; `x!` is checked at run time — a `null` aborts, alike on every target, with the location and the expression, a program error like `panic` (330; printed as every panic is, `panic: value is null — nome! at main.bp:3:13` — 492, 535, 731 (1)). `Result`'s declaration and value shape are § prelude-and-primitives (609). `Result<void, E>` is real — an assertion answers it with a bare `return;` in the `Ok` position — and a test body is a fallible context in which a propagated error fails the test (74).

(2) **Regions.** `try` opens a region; `catch` closes it and handles the failure of every `try` written in it: the region is the block `try { … }` when written, else the whole expression left of the `catch` — `(try a) + (try b) catch 0` sends both failures to the one `catch` (595 (1), (2)). The handler is an expression (the fallback), a `throw` (`catch throw ParseFailed`), a block whose value is the fallback, or a block with a binder `catch { e -> … }` — a `case` arm's binder, typed by the region (595 (3), 656). The region is an expression whose value is its last expression without `;`; an empty handler `catch { }` is `catch-empty` — a failure is handled or left to propagate, never swallowed in silence; a `void` region's handler is a block with at least one statement (595 (4)). One `E` per region: a second error type is `try-region-errors-differ` at that `try`, naming both — handle one on the spot or convert it (`catch throw …`) (595 (5)). A `try` in the handler's body belongs to the enclosing region or the function (595 (6)); a region holding no `try` is `try-region-cannot-fail` (595 (7)). Lowering: one early-exit block per region on each target — commonJS a labelled block or a sentinel, erlang / beam `try … catch` over a term of its own, wasm `block … br`; no new exception on wasm (595 (9)). Precedence: 537 (§ functions-lambdas-and-blocks (5)).

(3) **Crashes and `attempt`.** `panic` and an unannounced host raise are defects, never in a signature; `import {failure.attempt, failure.Failure} from "std"; val r = attempt({ -> plugin(x) });` answers `Result<T, Failure>`, the one way to contain one; `attempt` alone catches `panic` / `crash`, `catch` only a `Result`'s failure (431 (3), 595 (8)). `attemptTask(f: fn() -> Async<T>) -> Async<Result<T, Failure>>` is `attempt`'s task form (494); `asserts.throws<T>(body: fn() -> T)` is generic, over `attempt` (493). `Failure`'s kinds, exact on every target: `panic` — `panic(…)`, `x!`, an overflow, a division by zero (integer, and float on erlang and beam), a failing `assert` (`assertion failed: x > 0 at src/main.bp:12:5`, with the program's message when given); `host` — a raise from a binding without `result: true`; `crash` — a VM or emitted-code fault, a wasm trap, any unmarked raise; wasm never imitates a host raise (492, 527, 546, 675). A `crash` prints `crash: <the engine's reason>` on each target; a cell claims `stderr crash:` alone (556). An uncaught run-time abort writes to stderr the `Failure` an `attempt` would have caught, `<kind>: <message>` — `panic: division by zero: / on f64 at <file>:<line>:<col>`, `crash: <reason>`, `host: <message>` —, never the raw `Class:Reason` term; on commonJS the entry module itself installs the handler under its `require.main === module` branch, so `node main.js` prints the same (870); the departure declared in a cell is only whether the target aborts (535, 675). `attempt` on wasm uses wasm exception handling (`try_table` / `throw`) on every host, so `attempt({ -> panic("x") })` answers `Error(Failure(message: "x", kind: "panic"))` as elsewhere (518, 491, 543). A library sidecar that unwinds with a thrown term through a `host`-wrapped call is a library gap, never a compiler mechanism (554); `rakun-bpp`'s navigation signals become data its renderer reads (527 (5), 504).

(4) **Hosts and std.** `result: true`, `HostError` and the wrapping rule are § host-functions (4) (490, 489, 488, 546). Every std module that can fail answers its own error enum (`FsError`, `JsonError`, `EncodingError`, `RegexError`, `ProcessError`, `ClockError` …; `HttpError`, `StoreError`, `ActionError` their modules'); the binding stays private, writes `result: true` and answers `Result<T, HostError>`; the public function maps it into the module's enum in std (Node `ENOENT` and erlang `enoent` → `FsError.NotFound(path)`); a named variant is the same on every target; every failure the templates already handle gets a variant, a `Host(HostError)` variant holding only the rest (486). Every std binding is audited: one whose host call can fail gains `result: true` and the module's enum; one that cannot is listed in `libs/std/AGENTS.md` as promising no failure (495). `testing.asserts` imports on wasm, its API unchanged: `throws` / `throwsWith` over `attempt`; `matches` waits on std's regex there, a located refusal at the call until then (503). Every action answers `Result` (303) and every store `Result<T, StoreError>` (304) — § actions-http-log-routing, § rakun.
