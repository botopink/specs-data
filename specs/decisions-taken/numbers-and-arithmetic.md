# numbers-and-arithmetic — literals, widths, overflow, `bigint`, `Decimal`

**Kotlin's lowercase suffixes; a literal never changes type to fit; integer overflow is a program error on every target; `i64` is a real 64-bit integer everywhere; big numbers are exact.**

(1) **Literals.** `1.5` is `f64` and `42` `i32` by default; `1.5f` f32, `1.5d` f64, `42l` i64, `42u` u32, `42ul` u64, `42i8`, `42i16`, `42u8`, `42u16`, `42isize`, `42usize`; an uppercase suffix is a located error naming the lowercase one; a literal without suffix never changes type to fit: `val f: f32 = 1.5` and `val x: f64 = 1` are errors (247). A `bigint` literal carries the suffix `n` (332 (1)). An integer literal past its type's range is refused by the checker on every target (319).

(2) **Overflow and ranges.** Integer overflow is a program error on every target: `+`, `-`, `*`, unary `-` and the compound assignments of every integer type check the result against the declared type's range and abort; commonJS and erlang / beam add a range test per operation; no target wraps or answers a wider number (264). `abs` aborts past its type as unary `-` does, declared per width (`I32`, `I64` — now the types `i32`, `i64`, 641), `lo64().abs()` aborting on every target (496). `i64` and `isize` are −2^63 … 2^63 − 1, `u64` and `usize` 0 … 2^64 − 1, on every target; on commonJS a hybrid representation — a value within ±(2^53 − 1) a JS `number`, one beyond it a `BigInt`, always in that canonical form (`5` is never `5n`), each operation keeping its fast path and promoting only when the result leaves the safe range, 264's check aborting past the type's own bounds; the narrower integers stay JS numbers; crossing to JavaScript is explicit and exact (`toF64()`, `toI32()` abort when the value does not fit); a Node host template receives and answers `number | bigint`; the `.d.ts` types them `number | bigint` (319). `string.parseInt()` answers `Error` past the `i64` range (176, 319).

(3) **Division by zero.** An integer division by zero on erlang and beam raises a marked `panic`, as commonJS does (527 (3)); a float division by zero on erlang and beam is the same `panic`, `panic: division by zero: / on f64 at <file>:<line>:<col>`; commonJS and wasm answer `Infinity` (675, 444); at build every division by zero is a build error at the operator (472, 533).

(4) **`bigint` and `Decimal`.** `bigint` is a primitive integer of any size with every integer operator; erlang / beam the VM's integer, commonJS `BigInt`, wasm the runtime's — one value on the four targets (332 (1)). A `bigint`'s type stays static: it does not widen to `unknown` (`bigint-widened`), `is` neither tests for one nor tests a value holding one (`bigint-type-test`), a `comptime` computing one is `comptime-bigint`; `print`'s variadic `unknown` takes one (501). std's `Decimal` is the exact decimal (an unscaled `bigint` and a scale): `add`, `sub`, `mul` exact; `div` takes a scale and a rounding mode and has no form without them; `toString()` writes the scale (332 (2), (3)); `Decimal` stays in std, `Json`'s numbers are the `json` library's (500).

(5) **Counters.** `Dict.bump(key, by) -> Dict<K, V>` for an integer `V` alone — an absent key counts from 0, `insert(key, (at(key) ?? 0) + by)`; on a `Dict` whose `V` is not an integer the call is refused, located; a plain `Dict` method, atomic on the BEAM as `x = f(x)` on a module `var` (340, 534, 547 (ii)); `counts[k] += 1` stays out of the grammar (340).
