Decision 1005 (p6-c), the maintainer's design:
- `conformance/run.sh --target <t>` (or its botopink equivalent) walks the root package's module list itself, on the pool: per module, its `.bpr` (comptime, target-free, 805) built when missing or stale, then the runtime of <t>, each module its own process; a module that fails to build, crashes or hangs is its red alone; count held to the list.
- `botopink run --target <t>` in a package reuses its `.bpr` when the key matches (package + dependency sources + compiler binary), builds it otherwise; a stale .bpr never runs. erlang then beam then commonJS → comptime once.
- No driver: each run its own erl / node / wasmtime; runtime, generated code and exit contract (999, 870, 56) unchanged.
- CI: one job builds every module's .bpr fresh and publishes them as an artifact (like the compiler binary); one row per target downloads and runs; the workflow names targets, never modules.
- Cells: module_bpr_reused_across_targets, module_bpr_stale_rebuilt.
