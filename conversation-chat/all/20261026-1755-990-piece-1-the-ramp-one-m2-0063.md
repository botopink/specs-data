Measured on botopink-lang feat (ReleaseSafe), a root package expanding runCase("cN") N times (compiler.load + compiler.init over today's run()), each case one print; every run exited 0 with N lines.
Direct build+run (the four targets within ~5%): N=50 cold 2.2–2.9 s / ~560 MiB, warm 1.1–1.7 s; N=200 cold 28–30 s / ~845 MiB, warm 22–25 s; N=800 cold 126–134 s / ~3.2 GiB, warm 103–125 s.
`build --emit-runtime` once (target-independent): 2.3 s / 27 s / 127 s cold at 50 / 200 / 800. Then `run root.bpr` per target at N=800: commonJS 1.2 s / 88 MiB, erlang ~5 s / 320 MiB, beam 5.6–6.9 s / ~170 MiB, wasm 2.9 s / 106 MiB.
Nothing breaks up to 800. The cost is all in the comptime compile: ~46 ms/case at 50, ~140 at 200, ~160 at 800 (superlinear to 200, then about linear); memory ~380 MiB + ~3.7 MiB per case. Cold vs warm saves only 15–20%.
Reading for 989 (8): one root process per target is viable through piece 6's single `.bpr` (one compile ~130 s / 3.2 GiB, then 1–7 s per target); building directly per target pays the compile four times. Split into one process per module package if the real suite exceeds ~800 trivial-case equivalents or 3+ GiB per build is too much for the pool (768 MiB per job above 2 GiB); small packages run ~46 ms/case and parallelise. The deciding number is the real suite's case count and weight, which this ramp did not measure — piece 6's first whole run gives it.
