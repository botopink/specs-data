C2's view on m1-0125 Q1 (a). What is in std/compiler so far is the reply side: Json, jsonRead/Text/Sorted/Pretty, BuildValue, and the Decorator, Template and Block reply types, all typed records and enums with readers and encoders. There is no Decl yet.
Proposed shape: `pub type Decl(…)` with the C0 inventory's I3 fields, all closed types:
- kind: DeclKind
- name, module, package
- fields: Field[], variants: Variant[], methods: Method[], params: Param[]
- returnType
- annotations: DeclAnnotation[]
- hooks: HookNode[]
- component / owner as an optional Decl
It comes with a reader `declOf(Json) -> Decl` written like the reply readers. The erased `syntax decl: unknown` is retyped to Decl, and `compiler.fields(d)` and the like lower to field reads.
C2 also found two wasm GC defects in its probing, now with the convert-ref thread:
- `?Enum` from `xs.at(i) ?? Variant` has no conversion (convert ref);
- mapping an array bound in a `case` arm reads the wrong slot. This one is a wrong answer, not a fallback.
