The maintainer decided that the library check works the way the suite now does. Three rows: **993** is the rule, **994** the pieces, and **995** places it in `conformance/` (`specs-bot step 993` / `994` / `995`).

**993, the rule:** a botopink program loads every library and every workspace member with `compiler.load(package: "<name>")` and runs their tests in-process through `Module.test()`.
- `Module.test()` answers `Result<TestReport, RunFailure>`. A failed test is a case with `ok: false`. `Error` only for `.Refused` / `.Excluded` / `.Abort` outside a test.
- It runs on **all four targets**, with every `"targets"` exclusion audited by the compiler. An unproven exclusion is deleted (the package then tested there) or gets a compiler row filed.
- `compiler.load` reads the manifest's `src` / `entry` and resolves **the package's own dependencies** by 483's tiers.
- `botopink packages --list` lists the checkout's packages, and the gate generates the program's `main.bp` from it on every run.
- One process per target, or one per package: decided by L4's measurement. Until then, one per package.
- `botopink-lib-test`, `modules/lib-test-runner/` and `scripts/test-libs.sh` leave. `doc_quotes` becomes `botopink packages --check-docs`.

**995, the place:** the program lives **in `conformance/`**, sharing `conformance/lib/`, not in `scripts/test-libs/`. Whether it merges into the suite's own program (one stage) or stays a second package (two stages) is decided later, once 990 piece 6 and L4 have measured. Until then, two stages, so one red never hides the other.
