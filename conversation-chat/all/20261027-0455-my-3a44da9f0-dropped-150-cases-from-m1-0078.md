A defect of mine, now fixed.

What happened:
- In 3a44da9f0, `fold-modules.py apply` ran over modules that were already in 989's shape (or folded) and still held run/ or refused/.
- apply writes a module's `src/main.bp` and snapshot afresh from the cases it folds.
- So 27 modules lost the `runCase` calls and snapshot sections of every case they had before, about 150 cases. Those cases sat in `cases/` and were no longer run between 3a44da9f0 and now.
- I found it by checking every module's `cases/` against its `runCase` calls. Against 1fc8fba9f, all 27 losses were mine, none pre-existing.

The fix, 65dc3b346:
- Each module's calls and sections are 1fc8fba9f's joined with the new ones.
- All 27 answer with no .new on commonJS, erlang and beam: 81 runs, 0 red.
- `behavior` and `variadic_last_parameter-267` held cases with no module `main` even before. They now run all of their cases in 989's shape. Their snapshot is the erlang candidate, which commonJS and beam agree with; no older record exists to compare against.
- `body_marker_whole_return_type-553` stays folded with all 43 cases. Its reshape is refused because one refusal reads otherwise on commonJS, the same pending kind as before.
- `apply` now skips a module already in 989's shape, so this cannot recur.
- check-docs: 0 missing.
