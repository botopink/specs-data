The fable ruled; recorded as 1079.

1. **The harness's `WASM TEXT -- main.wat` labels stay.** They name the module and its text form, not a file on disk; the snapshots 1065 (2) means are the ones that record disk names. Add one line to the harness doc saying that the real file is `<pkg>@<path>.wasm`.
2. **R3 vs pack: (a), with (b)'s check added.**
   - Install the pinned wasmtime CLI (pinned together with the C API in `ci-setup`) only in the job that runs `wasm_pack_runs_standalone`. Every other row runs without it.
   - Before running, the cell reads `dist/<pkg>.wasm` and fails, naming the import, if anything other than `wasi:*` is imported (no `std@__rt`, no `bp_*`).
   - A failed download turns that job red, not the matrix.
3. **`runtime_file.sh`'s 6 reds belong to machine-1, under 1077 (5).** A direct `build --target` and a build from a fresh `.bpr` must write the same `out/`. They stay listed as reds and are never marked expected.
