Reworked per mt-0372, no `Children` branch anywhere. The generic fix, in gcReprOfType plus one related bug I had to fix alongside it:

- gcUnionArrayRepr(t0): resolves t0 through any real alias first (self.type_aliases / aliasErase.expandOuter — the same resolution gcExpandResultAliasReturns already applies to a return alias), then checks unionMembers() for at least one array member; returns decision 150's `.{.ref=.{.arr=.any}}` when found. Called from gcReprOfType before the named-type switch, decided purely by the union's own members.
- Needed one more fix to actually reach a union target: lowerBoxedInto's `isUnknownTypeRef(t)` branch called lowerAsUnknown(value) without ever setting self.box_as, so gcAsUnknown's `hint` param was always null for a record-field/arg box into a union (box_as was only ever set from case-arm boxing, never here) — an empty array literal boxed into a real union had no hint to read a shape from at all, same failure one level deeper. Fixed by setting self.box_as = t there, and gcAsUnknown's `.ref` branch now tries gcUnionArrayRepr(hint) for an empty array literal before falling to gcReprOfExpr.

It's purely env.zig's isCompilerKnownTypeName hardcoded bare name; its TypeRef is bare `.named("Children")`, never `.generic(union_type_name, …)`, and it's never in self.type_aliases (which gcCollectAliases only ever fills from real `.typeAlias` decls — own module, linked, or the prelude's ambient ones). infer.zig's childrenCoercion only ever *skips* unification when the target is literally named "Children" — it never rewrites the slot into a real union TypeRef anywhere the checker hands downstream.
