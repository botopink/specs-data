P3 is on its branch (`2a624f558`, rebased on P1), not landed yet.

What it does:
- `codegen/wat/runtime_unit.zig` builds one program-independent core module, `std@__rt`. It holds the exported memory, `__heap_ptr`, `__alloc`, every `std:` export of std-wasm decoded whole, `fd_write` / `random_get` (the only unit importing WASI), and the tag `$__bp_panic`.
- The entry imports all of these. `build` writes `out/wasm/std@__rt.wasm`, once per stamp.
- The component frame instantiates `$rt` first and passes it to `$main` with `with`.

Proof:
- New CLI test `wasm_runtime_unit.sh`: the entry carries no std functions, is under 50 KB, and gives the erlang answer. It is red on the parent and green after.
- 345 wasm snapshots re-recorded; I checked that 0 RUN LOG blocks differ.
- 13 conformance modules give the same wasm answer as before.

Entry core module sizes: hello-world 7.3 → 6.6 KB; with print/float/split, 116 → 16 KB.

Not moved yet: the `.wat` leaves and `$__write_bytes` (they name the caller's GC types), the scheduler globals, the shared table and the registry (no second unit uses them before P4), and `bp_host` / `bp_fs`.

Questions (recommendation first):
1. **The composed `main.wat` grows.** The component text embeds the whole runtime unit, so hello-world's `main.wat` goes from 14 KB to 748 KB, and wasmtime parses that text on every run. Programs that reach std/io/fs were already about 740 KB, so for them this is no change; it is a regression for small programs.
   (a) land it now and do the binary component encoder (1021 (1)'s later option (b)) as a P5 sub-piece, so the frame references `std@__rt.wasm` bytes instead of text;
   (b) hold P3 until that encoder exists;
   (c) land it as is and revisit after the P8 measurement.
2. **A new limit:** an entry's data must fit in a 16-page (1 MB) reserve above the runtime unit, and a bigger entry is refused with a located message. Large `@embed` data could reach it.
   (a) size the reserve from the entry's own data at link time, so there is no fixed limit and no new refusal (a P3 follow-up before landing);
   (b) keep 16 pages and the refusal;
   (c) a larger fixed reserve.
3. **Where the `.wat` leaves and GC print helpers move** into the runtime unit: (a) in P4, with the rest of the cross-unit wiring; (b) as a P3 follow-up now.

My recommendation: 2(a) before landing, then land, with 1(a) and 3(a).
