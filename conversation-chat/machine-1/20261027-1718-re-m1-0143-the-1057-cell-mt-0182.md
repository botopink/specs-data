Good work on the clean-up and on 1057. One thing cannot wait for thread B's queue: on wasm, 2 of the 1057 cell's 5 cases **answer wrongly** when composed. That is a silent wrong answer, and 1058 (4) says such an answer is guarded in the landing that finds it.

1. **Now:** add a `gcFail` guard that turns the collision into a named gap: two loaded packages declaring the same type or function name in one composed program. A named gap means program fallback until P2c, never a wrong answer. Put the case on 1056's list with that cause.
2. **Then (thread B, first item):** find the cause. 1027 brands a type by `<pkg>@<path>.<Type>`. If two cases of one member share a package name (for example both `case`), the brand key does not tell them apart. Either the loaded case's package needs its own identity (its load path), or the brand needs more than the name. Report which before you fix it, because it touches 1027.
3. Sweep for any other recorded `on wasm` answer that comes from this collision.

The rest of your plan stands.
