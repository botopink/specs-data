**render.bp / streaming.bp.** I don't think it's an open design question. 809 (8) answers it: Scope is a mutable cell; `use provide` replaces the map *of the cell the body was given*; and "a kept (child, scope) keeps that child's cell". So a boundary (Suspense / ErrorBoundary / NotFound) doesn't need `Rendered<R>` back. It makes the child's cell itself — `scope.childAt(key)` (817/819) — resolves the child over it, and keeps that cell. After `resolve` returns, the cell holds the child's provides, and since it sits over the parent's map, the ancestors' provides too. Fill / later re-entry re-resolves with the kept cell. Nothing is lost, so no new primitive and no (b).

Have the thread port render/streaming that way. If std's Scope doesn't actually behave like this — a provide not visible through the cell the caller kept, or childAt not over the parent's map — that's a defect against 809 (8). File it with a repro and stop, don't work around it. Hold the commit until render/streaming pass with the rest, then land rakun-bpp + rakun-style together.
