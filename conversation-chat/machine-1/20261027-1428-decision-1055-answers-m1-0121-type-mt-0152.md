The fable decided Q1; the maintainer agreed to Q2. Recorded as 1055.

**Q1: the type registry has no key.** Add a prelude supertype `$__decl` (non-final) whose first field is `(ref $__tinfo)`. `$__tinfo` holds the name `<pkg>@<path>.<Type>`, the `print`/`eq`/`display` funcrefs (display null when there is no `Display`) and `kind`.
- Every record and variant becomes `(sub final $__decl …)`.
- The core prints, compares and displays by casting to `$__decl`, reading `info`, then `call_ref`.
- `is` stays a `ref.test`.
- A unit's `__bp_init` builds its tinfos before its module `val`s and appends each to a core list, used only by typeinfo and debug.
- A type that lives in two units has two identical tinfos; nothing is deduplicated.

**Q2: closures become funcref** (this amends 1021 (4)): `{fn funcref, arity i32, mark i32}`, called with `call_ref`.
- Declare each lambda with the prelude's `$sig_n`. A structurally equal signature outside the group fails the cast; the fable confirmed this on wasmtime 45.
- Add `elem declare` for every lambda.
- `fn/N` reads `arity` (1051).

**Also:**
- Capture moves to the core: an exported `arrayref` global, `__cap_begin`/`__cap_end`, `$__write_bytes`. The entry's init resets it.
- Module `val`s are reached through exported accessors (`get_x() -> anyref`), never through exported mutable globals.
- 1037 (2) now reads: leaves are final; `$__decl` and `closure` are the two abstract supertypes.

**Order:**
1. P4a: prelude types and funcref closures.
2. P4b: registry, core print/eq/display, capture in the core.
3. P4c: `val` accessors, exported methods and implement. Only generics stay templates.
4. C1.

Each piece lands with its unit snapshots and the whole wasm row. Cells, each red on the parent: `wasm_foreign_type_prints` and `wasm_closure_crosses_units`. C2 and C3a do not wait on any of this.
