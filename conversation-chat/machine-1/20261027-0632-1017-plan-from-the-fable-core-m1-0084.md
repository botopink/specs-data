The fable's plan for 1017 (the coordinator holds the full text). Nothing past P0 starts before you answer the questions below.

**Design**
- **Units:** each unit `<pkg>@<path>.wasm` is a core module, not a component. A component boundary copies values (canonical ABI), so a GC struct cannot pass between components. `wac` / `wasm-tools compose` only compose components.
- **Composition:** the compiler already writes a component text frame (`renderComponent`). It grows to N core modules: one `core instance` per unit, instantiated in dependency order with `(with "<dep>" (instance $<dep>))`. `run` calls each unit's `__bp_init`, then the entry's `_start`. No external tool; wasmtime is the only pin. Checked on this machine: a tag, a GC global and a function cross core instances inside one component (wasmtime 45, `-W gc,exceptions`).
- **The runtime unit:** one program-independent unit, written once per compiler stamp. It holds the memory, the allocator, std-wasm decoded whole plus the `.wat` leaves, the host imports, the panic tag, the scheduler, one shared function table and a type registry. Every other unit imports it. Today std-wasm is 72 % of each entry.
- **Canonical types:** a fixed prelude rec group in every unit. Then one group per strongly connected component (SCC) of the declared type graph, ordered by `<pkg>@<path>.<Type>`, each field typed from its declaration. Then the unit's private types. Byte oracle: two units that name one std type carry identical shared groups.
- **Closures:** one shared table, with a base per unit. **Foreign-type print / `==` / `is`:** each unit registers its types in the runtime unit's registry.

**The linear fallback's end**
- No retry in `.linear`: each gap becomes a located refusal.
- Gaps to fix in the GC lowering, one cell each: string ordering (`$__str_cmp`); the `catch { e -> … }` binder; an `if` answering `null` or a value; a nested `if` beside an appending `else if`; a `case` arm that assigns; `"${e}"` of an enum; a `.Wasm(body:)` `-> void` leaf that leaves a value; and `bigint`, which today has only a linear form.
- The retry is removed only after a `gc_debug` inventory of every conformance module comes back empty.

**Pieces** (P1 / P2 can run in parallel with P3; P4 needs P1, P2c and P3)
- P0: `build --target wasm` writes the entry only. Running now.
- P1: canonical type groups. opus.
- P2a: the gap inventory. sonnet.
- P2b: the gaps fixed, eight cells. opus.
- P2c: the retry removed. opus.
- P3: the runtime unit. opus.
- P4: one unit per module, with cell `wasm_unit_per_module_linked`. opus.

- P8: measurement and docs. sonnet.

**Questions for the maintainer** (recommendation first)
1. **The composed program's form:** (a) component text with the units spliced in, no tool; (b) a binary component encoder in the compiler, later; (c) a `wasmtime --preload` chain, which loses `wasi:http` and the p2 host tasks, and leaves `build` with no artifact.
2. **The runtime unit's name:** (a) `std@__rt.wasm`; (b) `__bp_rt.wasm`; (c) a second `zig build std-wasm` artifact.
3. **wasmtime pin:** the CLI on PATH is 45.0.0; the C API is pinned at 49.0.3. (a) pin the CLI to 49.0.3 in `ci-setup` and the install docs; (b) leave it unpinned.
4. **Closures across units:** (a) a shared table with a base per unit; (b) a `funcref` field and `call_ref`.
5. **Foreign-type dispatch:** (a) a registry in the runtime unit; (b) the entry imports every unit's dispatcher.
6. **Cyclic module imports:** core instances link as a DAG. (a) refuse a cycle on wasm until one is met; (b) late binding through funcrefs.
7. **What a unit exports:** (a) `pub` declarations plus the per-type helpers, and everything for a module under test; (b) everything.
8. **`bigint` on wasm:** (a) give it a GC form in P2; (b) refuse bigint modules on wasm until later.

Risks: every wasm snapshot is re-recorded twice (P1, P3); P2c can turn red modules that ran on linear memory without saying so, which is why it waits for the empty inventory.
