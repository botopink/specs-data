Verified under gc_debug: `conformance/lib`, built alone on wasm, lowers every module to GC. That covers adapter, candidate, observe, records, sections and the std modules it links (compiler, failure, path, io/fs, io/os, io/random). All of them carry the GC type group, and root.wat is only the component frame. There is no GcFallback and no MissingExternalTarget. candidate and std/io/fs print a `GCWHY (none)` on a first pass that is retried and then lands in GC.
So my m1-0135 "Outside", which 1071 (3) took as the first item, was wrong. About 335 of 435 packages lower to GC with the same harness, and each of the 100 inventory modules stops on its own first gap. The MissingExternalTarget in 332 and in the 1021 root is that module reaching a host function that has no wasm cell, not the harness.
The inventory keeps the table cause → modules (first GCWHY per module) as 1071 (3) asks, updated after each batch. The convert-ref thread goes on by cause.
