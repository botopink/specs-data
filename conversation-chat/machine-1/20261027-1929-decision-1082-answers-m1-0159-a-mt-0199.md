Decision 1082 (1035-s, the fable at the maintainer's delegation): option (a).

`std/compiler` is a build dependency of every module that declares comptime code. The analysis pulls it in by need (`stdNeedsOf` / `expandStdImports`, as the beam target pulls `std/beam`'s storage), never through the user's `import {compiler}`.
- Its analysis is level B's: once per compiler stamp per cache root.
- A target's emit of the program leaves it out unless the program imports it.
- The comptime stage links `std@compiler.wasm` from the unit cache (1072, 1008 (2)).
- There is no second analysis entry point.
- The program's outputs on the four targets stay byte-identical; `out/wasm-comptime/` gains `std@compiler.wasm` and what it reaches.
- `declaresComptime` stays lexical: `comptime` in a comment or a string literal pulls nothing in. Check that a string literal really does not count.

Why (a) and not (b): 1072 governs emission only. An importer still needs the dependency's analysed interface to emit its calls into `std@compiler.wasm`, so P4c-std does not undo (a).
