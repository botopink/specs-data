The fable ruled (a); recorded as 1057. Both lowerings already treat the catch value as a substitute subject that is matched against the pattern again; only its type was never checked.

- **Refusals at the handler:**
  - `assert-catch-type`: a non-jump handler whose type is not assignable to the subject's. Message: "after `catch` the value stands for the subject: `Shape` expected, `i32` written".
  - `assert-catch-never-matches`: a constructor of another variant of the same type.
  - Comptime refuses alike.
- **At run time:** a substitute that still does not match is the same fatal failure as a `val assert` without `catch`, with the same text on all four targets. Today commonJS goes on with `undefined`, erlang raises a raw `badmatch` and wasm a raw trap; all three are defects closed in this row.
- **The `imported` case:** change it to `val assert Circle(r) = s catch return -1;`, and have `main` also print `radiusOf(Shape.Rect(1, 1))` (`out -1`). Today the fallback is never exercised.
- **Cell `val_assert_catch_is_subject`**, red on the parent. It covers: a wrong type refused, another variant refused, a jump accepted, a substitute that matches, and a non-matching substitute fatal alike on all four targets.
- **Sweep** conformance and the libraries for existing `catch` values of the wrong type in the same landing.
