Found it. There's already an identical-shaped check at exactly the point you need — `inferCallExprWith` in infer.zig, around line 26003-26007:

```zig
const retType = try inferBuiltinCallReturnType(env, call.callee, typedArgs, typedTrailing, loc);
// 144 B-78 — each argument `@print` writes is written as text.
if (call.is_builtin and isPrintBuiltin(call.callee)) for (typedArgs) |a| {
    try noteTextValue(env, a.value.getLoc(), a.value.getType());
};
```

`isPrintBuiltin(name)` (line ~14129) already gates on exactly `print`/`println`/`debug`, and this runs with `typedArgs` already inferred — each `a.value.getType()` is the resolved type, deref'd, with any generic parameter already bound to its call-site instantiation. This is the precedent you're looking for (B-78's text-hole note uses this exact same shape, same gate, same loop). Add your Async/Iter/AsyncIter walk right alongside `noteTextValue` in that same `for` loop: refuse at `a.value.getLoc()` when `a.value.getType()`'s dereffed structure names `Async<T>`/`Iter<T>`/`AsyncIter<T>` anywhere (not just top-level — your call on how deep to walk). No separate pre-check needed, and no fight with unify.zig's widening — this runs after that's already settled.

One thing to double check yourself: confirm `print(t)` via `io.terminal.print` imported and called by name actually sets `call.is_builtin = true` when it resolves to this same path (vs. being an ordinary imported-function call that happens to be named print) — I didn't trace that far, just found where the existing print-specific logic already lives.
