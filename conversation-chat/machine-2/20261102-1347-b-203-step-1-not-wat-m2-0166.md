Read it. Confirmed not refuseUnboundTemplateCalls (that's a distinct mechanism, generic-template unbound-parameter traps only). But it's also not a wat.zig reachability-attribution bug — it's structurally correct given the architecture, and the real gap is in conformance-lib itself, same family as B-170. Stopping here per guardrail 1, before touching any code.

The mechanism (`wat.zig`):
- `emitWat` tries the whole module `.gc` first; any GC gap anywhere falls the WHOLE module to `.linear` (not per-function — case_alternatives_and_arrays's own GC gap does this for the combined module).
- `checkLeafSignature` genuinely cannot let a `.linear` module call a `.wat` leaf — `.wat` leaves only exist for GC. That refusal is correct, not a bug.
- Decision 531's `reached_only` retry (meant to prune a dependency's unreached declarations and deliver exactly 518 (4)'s promise) does run here, but can't help: `candidate.bp`'s `finish()` — called unconditionally by every self-checking module's `main()` — *statically* calls `deliver()` inside an `if` whose condition is only false on a passing run. `deliver()` (which needs `io.fs.writeText`, hence `fs.cwd`) is therefore statically reachable from every self-checking module regardless of whether the run ever actually mismatches. Pruning only removes code nothing references in the source; this is referenced, just not executed on the happy path. So 531's escape hatch structurally cannot apply here — nothing in wat.zig is misattributing or over-reaching.

So the real finding: **any self-checking module whose own content needs `.linear` on wasm cannot build at all today**, because the scaffold's error-reporting path (`finish → deliver → io.fs.writeText`) is unconditionally, statically wired in, and `.wat` leaves are incompatible with `.linear`. B-170 already fixed conformance-lib's/`std/io/fs`'s own code so *it* never forces `.linear`; the missing piece is the mirror: conformance-lib's `io.fs` reference should not be *statically reachable* when the importing module needs `.linear`, so it doesn't drag the self-check scaffold down with it. That's a candidate.bp design question (how does a self-checking module report a mismatch on wasm, in `.linear` mode, without ever naming `io.fs.writeText`? maybe: never try to write the candidate on wasm at all, just the diagnostic text in the thrown error — the write was already best-effort, `written` is folded into the message either way), not a wat.zig fix.

Given this is now a conformance-lib scaffold decision rather than the compiler-internals fix we discussed, and it's shared code every self-checking module (not just the 67) depends on — want me to draft the specific candidate.bp change for your sign-off, or does this belong to someone else now that it's turned out to be B-170's territory rather than B-203's as scoped?
