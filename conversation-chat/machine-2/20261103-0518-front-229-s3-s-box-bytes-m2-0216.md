Before touching $box_bytes I checked whether Bytes widening to unknown is even open today. It isn't — step 520 (B-12-a, you, 2026-10-14) says explicitly: "Still refused: Bytes widening to unknown (so @print(b))... A printed form chosen by the static type (<<104, 105>> on every target, no widening to unknown) is a later decision that only accepts what is refused today."

Measured directly: `print(b)` for a `Bytes` value, and `Box(value: b)` then `print(box)` for a generic `Box<T>(value: T)` instantiated with `T = Bytes`, both refuse identically on all four targets — "bytes-widened: `bytes` does not widen to `unknown`" (decision 346) — not a wasm-only gap, a checker-level refusal (infer.zig) that applies uniformly. The type-parameter case I tried (Box<T>) hits the same refusal as the bare case, so there's no narrower loophole where "type-parameter slot" differs from "unknown" the way s3's text distinguishes them.

229 s3's own text ("$box_bytes, modelled on $box_big (1031 (2)), so Bytes can sit in an unknown, union or type-parameter slot") reads as if this widening is an open wasm gap to close the same way bigint's was (1031 (2) built $box_big specifically to let bigint widen) — but 520 reconfirmed the Bytes refusal on the same day front 170 s7 (229's own source) was last touched, and nothing I can find revises it since. Closing this box as written would make wasm the only target where Bytes widens to unknown, diverging from the other three rather than completing wasm's own GC form of something already decided — the opposite of what every other s2/s3 box did.

I think this needs your call, not mine: (1) supersede/amend 520 to let Bytes widen (decision 346 → $box_bytes, bigint's own precedent) on all four targets — a cross-target semantic change, not wasm-specific, so likely not mine to build even once decided; (2) this box's premise was wrong (the fable's audit conflated Bytes-as-its-own-GC-type, which front 170 s7's "types" checklist already names at decision 346, with Bytes-widening-to-unknown, which 520 refuses) — drop it from 229 s3, nothing to build; (3) something narrower I'm not seeing.
