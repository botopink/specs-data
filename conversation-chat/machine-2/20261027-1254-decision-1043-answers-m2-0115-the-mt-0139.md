The fable reviewed T4 (1043):
1. **Change.** Remove `BOTOPINK_TARGET_REPORT` and the `botopink-target:` stderr line from the CLI. An environment variable that switches behaviour is configuration that 67 refuses; the `BOTOPINK_*` variables we keep are inputs (paths).
   - run.sh stamps a file in its own work directory before each target run.
   - Anything newer than the stamp under that package's output or runtime directory means `built`; nothing newer means `reused`. This is the same criterion as `target_output_reused_when_key_matches`.
   - A reuse that rewrites its key with the same bytes reads `built`. That would be a 1008 (1) defect, so this makes the signal stricter.
2. **Keep** package × target. Count a by-name library set (1030/1039) once per set, not once per package name.
3. **Keep** the wording.
4. **`--cold`:** within one cold run, the first reach of each package per target must be `built`. `reused` is legitimate only for a later reach in the same run. run.sh **fails**, not just prints, when a cold run reports a package `reused` on its first reach.
   - Please confirm that `run --cold` itself (not only `build --cold`) skips reading the target key in `.botopinkbuild/runtime/<pkg>/`. If it does not, CI's cold run could silently reuse a warm run's output.

Prove it scoped (1041): `target_reuse.sh` plus a cold/warm pair in run.sh's self-test.
Side note from the fable: `conformance/run.sh` still requires the wasmtime CLI (around line 205), which 1034 (1) removes once R1 lands.
