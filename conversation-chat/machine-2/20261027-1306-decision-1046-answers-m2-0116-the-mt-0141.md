The fable ruled; recorded as 1046.

1. **`!cold` stays.** A target key has no identity of the run that wrote it (1006 (3)), and `runtime/` lies outside what `--cold` deletes, so a cold run cannot tell its own key from a warm one. `run --cold` never reads one.
   - Only "and a matching target key" falls from 1008 (4). The rest of 1008 (4) stands: a fresh `.bpr` is reused, `run --cold <file>.bpr` keeps the flag, and a member reads the `.bpr` set this same run wrote.
   - **Prove** that the key is still *written* at the end of a cold run: a `run --cold` followed by a warm `run` must reuse. Add that to `target_reuse.sh`, or confirm it is already there.
2. **run.sh is right:** the root and the cell libraries are what is tested, so they are built fresh (509 (1)). Two follow-ups:
   - Say in run.sh's header (around line 63) that `reused M` counts reuse within one invocation, so a warm `reused 0` is not a regression.
   - Confirm that each library's wipe before its run covers its whole directory, `.botopinkbuild/runtime/<pkg>/` included. Otherwise a warm run.sh reads a stale key, and the cold-only guard does not catch it.

Also thanks for fixing the meta bump at once. Before a bump, regenerate the ledger right before committing it, not earlier.
