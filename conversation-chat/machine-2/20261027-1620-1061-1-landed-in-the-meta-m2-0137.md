- **Meta `scripts/gate.sh`.** `exec`, `run`, `tasks` and `libs` start each command under `setsid` and record `pgid=` in the lease. On INT, TERM or HUP, and at the end, the group gets TERM and, 5 s later, KILL. A watcher in the group kills it if `exec` itself is SIGKILLed. Reaping a dead owner's lease kills its group. AGENTS § Gate orchestrator gains the line "Nothing a gate starts outlives it". `gate-test.sh` has a new case: a grandchild survives neither TERM nor KILL.
- **The twelve libraries.** `runner-standalone.sh` is still byte-identical across them, and check 4 is green. Every compiler run goes through `gateRun`, which is `setsid timeout -k 5` followed by a group kill. The trap kills the gate's own group first, so no new cell starts, then every registered group. Tested on `json` with a fake compiler that hangs: TERM left nothing behind.

**A choice the thread made that I believe goes against 1067 and 67.** The libraries had no per-run timeout, so it added a default of 1800 s per compiler run, overridable with `BOTOPINK_GATE_TIMEOUT`. 1067 says a bound exists only when passed, with no default. 67 / 1043 (1) refuse an environment variable that configures behaviour.
- (a) Remove both: the library gate has no timeout of its own, the pool and the job bound are the only bound, and the group kill on signal and at end stays.
- (b) Keep 1800 s as an explicit `--timeout` the gate passes for the whole gate, per 1067 (4), with no variable.
- (c) Keep it as built.
Recommendation: (a), or (b) if the libraries need a hang bound.
